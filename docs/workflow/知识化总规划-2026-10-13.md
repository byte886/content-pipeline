## 1. 概念层结构设计

### 1.1 形态定位：books / courses 归入 concepts 家族（形态②）

**BookNote / CourseNote 与 VideoNote / ArticleNote 同粒度（单来源原子笔记）、同生命周期（draft → stable → topics），并列喂 topics 融合层**；郭颖形态①（`type: Knowledge` 人工归并长文档）不动。理由与桥文档 §5 一致：书籍/课程是"单来源长文本"原料，逐册/逐集原子化后再跨模态归并，不塞进长文档。

### 1.2 concepts 类型词表（统一，回应待核④）

| 类型 | 来源模态 | 落点 | 状态 |
|---|---|---|---|
| `VideoNote` | 视频 | `concepts/videos/` | ✅ 老许 744 |
| `ArticleNote` | 文章/图文 | `concepts/articles/` | ✅ 顶底之王 278＋老许 20 |
| **`BookNote`** | 书籍/课件/图录/习题提取物 | `concepts/books/` | 🆕 本规划 |
| **`CourseNote`** | 课程转写稿 | `concepts/courses/` | 🆕 本规划 |
| `ReportNote` | 报告/长文 | `concepts/reports/` | ✅ 老许 1 |
| `Concept` / `Reference` | topics 页 / 参考材料 | `concepts/topics/` 等 | ✅ |
| `MethodNote` | 方法提炼 | `concepts/…` | design 已定义未实现（P5） |
| `Knowledge` | 人工归并长文档（形态①） | `05_knowledge/<域>/<主题>/` | ✅ 郭颖 23 |

OKF v0.2 只硬必填 `type`，其余宽容消费——新增 BookNote/CourseNote 不破坏校验器（试点时用 `okf_validate` 实证 E0）。

### 1.3 BookNote frontmatter 规范

```yaml
type: BookNote
title: <书名>（<章节/主题>）
description: "机器生成待核：<编译摘要 1-3 句>"
tags: [<域>, books, <主题>]
domain: jewelry | stock
content_type: 教材 | 课件 | 图录 | 习题 | 工具书 | 杂志
sources:
  - id: src-book
    kind: extracted_md
    resource: <07_books 提取物相对路径，如 ../../../07_books/jewelry/…/*_extracted.md>
    title: <提取物标题>
  - id: src-extract   # 仅当有 caj/raw 原件
    kind: raw
    resource: <原件相对路径>
    title: <原件名>
generated: { by: doubao/knowledge-unify, at: <ISO8601+08:00> }
status: draft
book_id: <书名slug>_<版本/年份>
engine: PyMuPDF文本层 | macOS Vision | caj2pdf | ebook解包
pages: <N>
clean: true | false
```

### 1.4 CourseNote frontmatter 规范

```yaml
type: CourseNote
title: <集名，如 36宝石资源、加工及商贸（八）>
description: "机器生成待核：<编译摘要>"
tags: [<域>, course, 宝石学, <主题>]
domain: jewelry
content_type: course
sources:
  - id: src-course-transcript
    kind: transcript
    resource: <04_transcript 相对路径，如 ../../../../04_transcript/jewelry/中国地质大学宝石学/<组>/<集>/transcript.md>
    title: <集名>
generated: { by: doubao/knowledge-unify, at: <ISO8601+08:00> }
status: draft
course_id: <鉴藏NN讲 | 翡翠物语N>
clean: false   # ASR 初稿未深度清洗（清洗深度见 §2.2 G7 门）
```

### 1.5 src 标签协议扩展

加入 `src-book` / `src-course-transcript`（既有协议：src-douyin / src-bili-video / src-bili-opus / src-wechat / src-xhs / src-pdf / src-audio / src-transcript / src-ocr）。**跨模态归并**：同主题下 books/courses 原子页与 videos/articles 原子页并进同一 topic，脚注 `[^src-book-*]`/`[^src-course-*]` 逐条溯源（对齐桥文档 §3 协议与老许 topics 先例）。

## 2. 批量 OKF 化流程（K2/K3）

### 2.1 两段式（复用 P3 引擎，`scripts/wrap_wechat_articles.py` 同模式）

- **阶段一（机械）**：幂等脚本生成 frontmatter 骨架/原子页，分批 **≤50**、只读原文；逐批校验 frontmatter 可解析＋正文字节未动。
- **阶段二（提炼）**：LLM 编译原子页（摘要 1-3 句＋3-5 要点＋来源指针），**不复制全文**——原文只在 `07_books/` / `04_transcript/` 存一份（对齐桥文档 §2 纪律）。
- 每批后：`okf_validate` E0＋数量对账；收尾统一 index 登记（`concepts/books/index.md`、`concepts/courses/index.md`，模式同 stock concepts）；提交前 `doc_health_check` 0 ERROR。

### 2.2 课程线清洗前置门（**G7，待用户拍板**）

实测 96 集为 ASR 初稿（语气词/假名/英文碎片/控制符残留）。三选一：
- **A（默认建议）**：直接 OKF 化，原子页标 `clean: false`＋`draft`；深度清洗并入 K4 质检（词典替换＋人工抽检），不阻塞知识化。
- **B**：先批量清洗（`clean_subtitle.py` 或词典替换＋人工抽检）再 OKF 化——工期长、阻塞依赖。
- **C**：提炼时 LLM 精读原文成稿（成本最高，质量最好）。

> 与台账"已词典清洗"矛盾：**待核**清洗是否已在他处执行（若已清洗则 G7 自动走 A 且 clean: true）。

### 2.3 范围（选择性原则延伸——用户原则：按需要的主题＋指定来源，非全量）

- **stock 29 提取物（md 19）→ 全量**（量小、主题明确）。
- **jewelry 654 → 按主题分批**：先高价值批次（宝石学教材/图录/鉴定考试），**评估课件 419 建议先索引级登记、按需提炼**（待拍板是否全量——419 个课件 OCR 大头，全量提炼成本高）。
- **课程 96 集 → 全量 CourseNote**（一集一篇，轻量原子页）。
