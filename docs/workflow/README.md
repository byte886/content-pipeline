# 工作流设计（workflow）

> **文档类型**：Reference（参考资料 — 目录说明）
> **更新频率**：目录结构变更时
> **维护者**：AI 自动维护 + 用户审核

> 本目录承载「博主视频 → 知识库 → 云文档」融合工作流的**主流程设计与流水线 SOP**，是 content-pipeline 流水线的流程层权威位置。
> 与 `docs/guides/` 的分工：**workflow/ = 端到端主流程、阶段、决策门、编排**；**guides/ = 单点操作 SOP**（如某平台采集、某工具用法）。workflow/ 引用 guides/ 与技能目录，不复制细节。

## 三层文档分工（先读这个，避免乱）

同一套工作流分三层，各司其职、靠链接互指：

| 层 | 文件 | 内容 | 什么时候看 |
|----|------|------|-----------|
| 导航层 | `../WORKFLOW.md` | 七阶段总览（S0–S7）+ 校验门速览，链接下两层 | 任何任务开始前，先看它确认在哪一阶段 |
| 决策层 | `视频知识工作流-融合规划-2026-10-12.md` | 为什么这么设计：现状评估、仓库归属、三大缺口、决策记录、待办登记 T01–T23、待核事项 | 决策 / 评审 / 接续新阶段时（**接续入口 = 其 §11 待办登记表**） |
| 执行层 | `workflow-main.md` | 怎么做：S0–S7 每阶段详设、决策门 G0–G6 速查、多模态路由矩阵、任务卡状态机 | 实际跑流程时，按它逐阶段执行 |

**AI 接手顺序**：先读 `../WORKFLOW.md`（定位）→ 决策看规划（含 §11 待办）→ 执行照 `workflow-main.md` 跑 → 产出后回写规划待办表状态。

## 使用规范

1. 新增本目录文档后，必须在 `../DOCUMENTATION_MAP.md` 登记（项目规则：新增文档必须登记）。
2. 涉及技能子能力的，先查技能目录是否已有实现，禁止在本目录重复写实现细节。
3. 事实标注来源路径；不确定标「待核」。
