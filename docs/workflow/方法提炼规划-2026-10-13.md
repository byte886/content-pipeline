# 方法提炼（MethodNote）规划

> **文档类型**：Process / 规划（方案先行，本轮只规划不批量执行）
> **日期**：2026-10-13　**状态**：方案待组织者拍板后启动试点
> **归属**：content-pipeline · P5 子项（MethodNote 类型实现；与融合规划 §6.4 / 知识化总规划 §1.2 词表衔接）
> **事实纪律**：每条方法信号标注来源路径 / URL；归纳证据不足处标「待核」；禁止编造博主意图与平台数据。

---

## 0. 一句话目标

知识库已有「原料知识」（懂什么：VideoNote / ArticleNote / BookNote / CourseNote / 郭颖 Knowledge 长文档）；P5 新增「方法知识」（怎么做：**MethodNote**——把"博主是怎么做内容、怎么做运营、为什么受欢迎"从原料中反推出来，提炼成可复用、可溯源、跨博主归并的原子页）。

**边界（红线区分）**：
- 「潘家园淘货实战手册」等已有知识文档讲的是**消费者怎么买货**（懂货方法）——属于原料知识，不进 MethodNote。
- MethodNote 讲的是**创作者怎么生产这条知识**：为什么这样选题、为什么这样讲、粉丝为什么买单、评论区怎么被利用——是元层（meta）知识。

## 1. MethodNote 类型定义

### 1.1 定位

与 VideoNote / ArticleNote / BookNote / CourseNote **同粒度、同生命周期**（draft → stable），但内容形态不同：不搬运原文，只输出**原则 / 模式 / 步骤 / 案例指针**。

### 1.2 frontmatter 规范（沿用 OKF v0.2，硬必填仅 `type`）

```yaml
---
type: MethodNote
title: "<方法名，动词短语，如 权威身份+接地气双轨信任建立法>"
description: "机器生成待核：<1-3 句说清这个方法是什么、谁在用、效果信号>"
tags: [method, <domain>, <content_type 类别>, <博主>]
domain: jewelry | stock
content_type: trust_building | content_strategy | audience_building | monetization | selection_method
sources:
  - id: src-transcript-*        # 见 §2 来源协议
    kind: transcript
    resource: <本地转写相对路径 或 平台URL>
    title: <视频标题>
    author: "human:<博主>"
  - id: src-comments-*
  - id: src-cloud-research-*
generated: { by: "doubao/method-note", at: <ISO8601+08:00> }
status: draft
method_id: <英文slug，如 authority-plus-grounded-trust>
blogger: <归因主体单博主时填>
applicable_to: [<博主A>, <博主B>]   # 多博主共用方法时填，与 blogger 二选一
evidence:
  count: <N>                    # 独立来源数
  multi_blogger: false | true    # 是否跨博主验证
  single_source_risk: true | false
---
```

### 1.3 content_type 词表（本规划新增，与用户给定枚举对齐）

| content_type | 含义 | 已观察到的信号实例（来源见 §5） |
|---|---|---|
| `trust_building` | 信任建立：权威背书、人设、预期管理、失败复盘 | 院长身份置顶片；"1000块买和田玉压力大"先泼冷水；"墨翠挑战失败"如实复盘 |
| `content_strategy` | 内容策略：选题公式、口播结构、记忆点设计 | "三问三不问""三招鉴别"数字结构；价格口诀韵文；情景剧开场 |
| `audience_building` | 涨粉与社群：评论区利用、粉丝参与栏目、争议话题 | 潘家园寻宝评论区征集；老许评论区"钻石算不算骗局"争论 |
| `monetization` | 变现与导流：线下一对一、私域、回收话术 | 潘家园一对一配首饰；"学院有培训班欢迎来系统学习" |
| `selection_method` | 选品/货盘决策框架（**只提炼"怎么挑"的通用框架，具体品类挑货知识仍留品类文档**） | 逛摊做减法、比货并排比、六维估价框架 |

> 边界注：`selection_method` 最易与郭颖品类知识文档重叠。判据——**页面回答"这货好不好"→ 品类文档；页面回答"博主为什么把挑货做成内容、挑货框架如何被包装成卖点"→ MethodNote**。

### 1.4 正文形态（四件套）

```markdown
# <方法名>

> 一句话定义（谁、对谁、做什么、为什么有效）

## 模式（3-6 条原则，每条挂证据脚注）
## 步骤 / 动作（可照着做的清单）
## 案例指针（链接到具体 VideoNote / 知识文档，不整段搬运）
## 为什么可能有效（效果信号：评论/互动/重复出现频次；证据不足标待核）
## 边界与反例（什么情况下不适用）
## 关联条目（反向指针：本方法派生自哪些原料页）
## 来源脚注
```

## 2. 来源标注协议

### 2.1 src 标签扩展（在既有 src-douyin / src-bili-opus / src-wechat / src-transcript / src-comments / src-pdf 基础上明确语义）

| 标签 | 来源 | 落点 | 用途 |
|---|---|---|---|
| `src-transcript-*` | 郭颖本地转写 `05_knowledge/jewelry/珠宝学者郭颖/transcripts/<标题>/transcript.md`；老许 `04_transcript/...` | resource 给相对路径 | 口播结构、口诀、情景剧等**内容方法主证据** |
| `src-comments-*` | `08_sources/douyin_comments/<vid>_comments.json`、`08_sources/bilibili_comments/<bv>_comments.json` | resource 给 JSON 路径 | **受欢迎信号佐证**（身份认可、提问、争论） |
| `src-douyin-*` / `src-bili-opus-*` | 平台原片 URL | resource 给 URL（标注采集日期） | 元数据（播放/点赞/发布时点） |
| `src-wechat-*` | 公众号文章 | 既有协议 | 图文方法 |
| `src-cloud-research-*` | 云盘研究稿（如《郭颖研究-为什么受欢迎》docx `Battd0Mddosu7vxcGwcc4YZDnif`） | resource 给云文档 URL | **已有人工归纳的二手证据**，降权标注 |

### 2.2 脚注溯源规则

- 与桥文档 §3 / 老许 topics 先例一致：frontmatter `sources[].id` 每个都在正文以脚注出现；正文每个脚注都能在 sources 找到背书（不新增野脚注，对齐 W60 基线）。
- **降权标注**：云盘研究稿是"一方归因"（其原文自述"非平台数据"），引用时在正文标〔研究稿〕；转写/评论为一手证据。
- **效果数据缺口（待核）**：粉丝量、互动率、爆款率目前**未采集**（研究稿原文待补项）；MethodNote 不得编造"涨粉XX万"类数字，效果论证只用：①多视频重复出现的模式频次；②评论区可采的原始 JSON；③置顶/高互动片的计数（如郭颖置顶片 251 赞、老许 BV1kK4y1w7UN 3.5万播放/68评论——均来自已采集 JSON meta）。

### 2.3 多博主同类方法的归并方式

- **同一方法、多博主都在用**（如"避坑选题""口诀化"郭颖老许皆有）→ **一页**，`applicable_to` 列双方，sources 并列两组证据，正文分"郭颖表现 / 老许表现"两小节对比。
- **某方法为单博主独有**（如潘家园评论区征集栏目）→ 单页 `blogger:` 归因，不硬凑跨博主。
- 归并判据：方法的**抽象层级**对齐（"借社会热点做避坑选题"是抽象方法；"翡翠直播间翻车"是单个选题，不上升）。

## 3. 与 topics 的关系：独立 `methods/` 容器（建议方案）

### 3.1 建议：新建 `library/05_knowledge/jewelry/concepts/methods/`，与 `videos/` `topics/` `articles/` `reports/` 平级

**不喂进 topics 的理由**：

1. **读者与用途不同**：topics（如"行情价格与选购话术"）Answer-First 是给**消费者买货**用的领域知识；MethodNote 是给**内容生产者/运营者**用的元知识。混进 topics 会让主题页速查被"怎么讲"的内容稀释。
2. **粒度不同**：topics = 一个领域主题聚合（255 篇次 VideoNote 融合）；MethodNote = **一个方法**一页原子页，与 VideoNote 一视频一页同构。
3. **可跨域复用**：方法论（双轨信任、口诀选题、评论征集）未来 stock 域或其他博主研究会复用同一套。先按域落地在 `jewelry/concepts/methods/`（与原料 bundle 同仓、反向指针好挂）；**待第二批试点后**再评估是否抽 `05_knowledge/methods/` 跨域方法索引——本轮不建，避免过早抽象。

### 3.2 命名与落点

- 文件名 = `method_id` 英文 slug（如 `authority-plus-grounded-trust.md`、`numbered-formula-topics.md`），与 VideoNote 用 BV 号、topics 用中文主题名的惯例错开，便于机器识别。
- 同目录建 `index.md`（登记 method_id / title / content_type / applicable_to / 证据数 / status），模式对齐 topics/index.md。
- 反向指针：topics 页"关联条目"区可链接到相关 MethodNote（如"行情价格与选购话术"↔"进店话术内容化"方法页）；MethodNote 正文"关联条目"链接回原料 VideoNote / 知识文档。**原料知识不因 MethodNote 改动**。

### 3.3 与郭颖形态①（Knowledge 长文档）的关系

郭颖 23 份 Knowledge 是"懂货"成品，**不拆不改**；MethodNote 从其成品结构 + transcripts/ 323 份转写 + 评论 + 云盘研究稿**反推**，只做指针引用。

## 4. 提炼流程（S1–S6，复用 evaluation-agent-template 五维质检门）

| 步 | 名称 | 动作 | 产物 / 门 |
|---|---|---|---|
| **S1 信号扫描** | 从三类原料识别方法信号：①转写标题模式（"几招/避坑/怎么买/三问"等，已实测命中 ~28 条）；②正文结构（情景剧开场、口诀韵文、案例复盘）；③评论 JSON（提问/争论/身份认可） | 候选信号清单（方法假设 / 证据路径） | 候选登记表 |
| **S2 候选登记** | 按 content_type 归类，标注：归因博主 / 证据数 / 单源风险 / 是否已被云盘研究稿覆盖 | method 候选表 | 每候选一行 |
| **S3 初稿（draft）** | 按 §1.4 四件套成文；只写原则/模式/步骤/指针，**不整段搬运转写原文** | MethodNote draft | `status: draft` |
| **S4 交叉验证** | 至少 **2 个独立来源**（转写 + 评论 + 研究稿）才算"可归并"；仅 1 来源 → `evidence.single_source_risk: true` 并在文中标「单源待核」；跨博主同方法 → `multi_blogger: true` | 证据对账 | 门：单源不得升 stable |
| **S5 质检门** | 机械门：`okf_validate` E0（必须 0）；复用 evaluation-agent-template 五维——A 事实准确（方法归纳不超出原文证据）/ B 来源可溯（sources↔脚注闭合）/ C 正文一致（description 不夸大）/ D 覆盖（候选信号有无漏收）/ E 待核处置（效果数据缺口如实标注） | 质检结论 | 门：E≠0 或野脚注 → 回 S3 |
| **S6 定稿** | 多证据闭合 + 质检通过 → `status: stable`；人工核过补 `verified: human:`（本轮试点全部停 draft，由组织者安排人工核后再升） | stable 页 | index.md 登记 |

> 与 K4 质检线关系：MethodNote 复用同一评估模板与校验器，不另建质检体系；试点后视情况把"方法归纳忠实性"（A 维度的子类）补进 evaluation-agent-template。
