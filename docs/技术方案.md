## 二、技术选型

### 2.1 视频处理

| 组件 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 视频下载 | res-downloader | 3.1.3 | 微信视频号抓包工具，本地代理127.0.0.1:8899 |
| 视频解密 | 自研Python脚本 | - | ISAAC64密钥流XOR解密前128KB |
| 视频压缩 | ffmpeg | 最新 | H.264 1Mbps + AAC 128k |
| 语音转写 | FunASR | SenseVoiceSmall + fsmn-vad | 本地离线转写，支持中文/英文/日语 |
| 视频播放器 | IINA/VLC | - | 验证视频可播放 |

**关键技术细节**：
- 微信短视频加密：前131072字节（128KB）用ISAAC64伪随机数生成器加密，之后明文
- 解密密钥：DecodeKey → WxIsaac64(seed).generate(131072) → 字节反转 → Base64 → XOR
- 直播回放：直接是标准MP4（H.265），无需解密
- 转写参数：use_itn=True，VAD单段≤30s，batch_size_s=60（脚本内固定，不要改）

### 2.2 微信数据读取

| 组件 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 数据库解密 | wx-cli | 0.3.0 | 微信本地SQLCipher数据库解密读取 |
| 微信版本 | WeChat | 4.1.8 | 锁定版本，关闭自动更新 |
| UI自动化 | mac_computer_use_tool | - | macOS AX树操作，相对坐标0-1000 |
| 浏览器自动化 | seed_browser_use | - | Chrome页面操作 |

**关键技术细节**：
- 微信数据库：SQLCipher 4（AES-256-CBC + HMAC-SHA512）
- 密钥提取：关SIP + sudo + 不重签微信，一次性提取永久有效
- 公众号文章表：`biz_message_*.db` 中的 `Msg_<MD5(username)>` 表
- 视频号直播记录：`general.db` 中的 `wcfinderlivestatus` 表
- 微信AX树：内部元素不暴露（仅9元素），需用坐标点击

### 2.3 公众号文章采集

**三方案对比**：

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| A. UI自动化打开缓存 | 内容完整，含图片 | 速度慢，需微信运行 | 历史文章批量采集 |
| B. 搜狗微信搜索+Chrome | 不依赖微信，速度快 | 可能被反爬，内容可能不全 | 新文章增量采集 |
| C. res-downloader抓包 | 可获取原始HTML | 需人工触发播放/点击 | 备用方案 |

**推荐方案**：A为主（历史文章），B为辅（增量跟踪）

## 三、核心模块设计

### 3.1 视频采集模块

```
scripts/
├── video/
│   ├── check_new_videos.sh      # 检测新视频
│   ├── download_videos.py       # 批量下载
│   ├── decrypt_videos.py        # 解密短视频
│   ├── compress_videos.sh       # 压缩视频
│   ├── transcribe_videos.sh     # 批量转写
│   └── organize_videos.py       # 分类整理入库
```

**数据流**：
1. res-downloader抓包获取视频URL+DecodeKey
2. download_videos.py 用curl下载（带UA和Referer）
3. decrypt_videos.py 用ISAAC64密钥流解密前128KB
4. compress_videos.sh 用ffmpeg压缩（H.264 1Mbps）
5. transcribe_videos.sh 用FunASR转写文字
6. organize_videos.py AI分类打标签，存入知识库

### 3.2 公众号采集模块

```
scripts/
├── article/
│   ├── check_new_articles.sh    # 检测新文章
│   ├── fetch_articles.py        # 抓取文章正文
│   ├── parse_article.py         # HTML解析提取正文
│   ├── ocr_images.py            # 图片OCR
│   └── organize_articles.py     # 分类整理入库
```

**数据流**：
1. UI自动化打开公众号历史文章列表
2. 逐篇点击，等待微信缓存到biz_message数据库
3. 从数据库读取文章内容（或搜狗搜索获取URL后Chrome抓取）
4. parse_article.py 提取正文、图片、发布时间
5. ocr_images.py 对文章图片做OCR
6. organize_articles.py AI分类打标签，存入知识库

### 3.3 知识库管理模块

```
scripts/
├── knowledge/
│   ├── update_index.py          # 更新索引文件
│   ├── search.py                # 关键词搜索
│   ├── extract_knowledge.py     # 知识点提取
│   ├── generate_template.py     # 文案模板生成
```

## 五、关键技术决策记录（ADR）

### ADR-001：视频转写用FunASR而非Whisper

**决策**：使用FunASR（SenseVoiceSmall + fsmn-vad），不使用faster-whisper

**原因**：
- Intel CPU上faster-whisper过慢（已验证弃用）
- FunASR SenseVoiceSmall对中文支持更好，财经术语准确率高
- multiplatform-media-fetch技能已内置，开箱即用

**后果**：转写参数固定在脚本内，不要随意修改

### ADR-002：短视频解密用Chrome WebAssembly而非Python实现

**决策**：在Chrome中加载res-downloader的decrypt.js，用WxIsaac64生成密钥流

**原因**：
- Python自行实现ISAAC64两次都不匹配（仅535/131072字节匹配）
- WebAssembly是官方实现，保证正确
- 密钥只需生成一次，之后用Python XOR解密即可

**后果**：首次生成密钥需要Chrome环境，后续解密纯Python即可

### ADR-003：知识库v1.0用纯文件存储，不用数据库

**决策**：v1.0用Markdown文件+JSON索引，不接入向量数据库

**原因**：
- 单人项目，内容量初期不大（<500条）
- 文件存储简单、可移植、可用任意编辑器查看
- grep/ripgrep搜索足够快
- 向量数据库增加运维复杂度，v2.0再评估

**后果**：语义搜索能力有限，后续可能需要迁移

### ADR-004：公众号采集用UI自动化为主

**决策**：历史文章用微信UI自动化打开缓存，增量用搜狗搜索+Chrome

**原因**：
- 微信数据库不主动缓存未打开的文章
- UI自动化虽然慢，但内容完整（含图片）
- 搜狗搜索可能被反爬，作为增量备用

**后果**：首次采集需要较长时间（每篇文章停留5-10秒）
