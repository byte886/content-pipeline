# 新窗口怎么接手这个项目（开新任务窗口 · 固定 SOP）

> 目标：**只要知道仓库位置，新窗口就能接手**，不需要老窗口复述背景。
> 冷启动读什么、什么顺序、红线、验收题，全部由仓库里的 `AGENTS.md` §1.1 与 `docs/项目维护SOP.md` §5 接管。
> 实测订正：选项目文件夹**不保证**项目 `AGENTS.md` 被自动注入——两步都要做，第 2 步的标准句是兜底。

---

## 0. 触发词（听到就走本 SOP，不自创交接长文）

用户说任一句："上下文有点大了，开个新任务窗口" / "换新窗口" / "新窗口接手" / "再开个窗口接着干" / "开个新任务接手"，当前窗口（=**老窗口**）立即按 §1 收口。

## 1. 老窗口收口（开窗之前，AI 做，四步）

1. **状态落盘**：本轮重要讨论/决策往 `docs/HANDOFF.md` §1 **倒序追加一条**（最新在上）；`TASK_STATUS.md`、`ISSUES.md` 更新到最新（易变进度只留台账）。
2. **体检**：仓库根跑 `python3 scripts/doc_health_check.py`，必须 **0 ERROR**（WARN 记录后可放行）。
3. **提交并推送**：`git commit` 后 `git push origin master`（本仓 public，按里程碑自动推送，不必每次问；凭证/sudo 需要时再问用户）。
4. **发操作指引**：把 §2 的两步和标准句**原样**发给用户，不再写长篇交接段落（仓库自描述，结论都在仓里）。

## 2. 用户开窗两步（本机，最简）

1. 新建任务窗口时，**项目文件夹选成 `~/Desktop/multiplatform-content-pipeline`**
   （不要用系统默认的 `~/Doubao/chats/...` 聊天临时目录——那里的 AGENTS.md 是旧的或缺失，会误导新窗口）。
   作用：定位仓库、工作目录落在项目里；**但不保证规则自动注入**，所以第 2 步不能省。
2. **只发这一句（标准句，原文照发）**：

   ```
   接手这个项目，按 AGENTS.md §1.1 冷启动，先把 docs/项目维护SOP.md §5 的冷启动六问答给我听，再等我派活。
   ```

   短句"按 AGENTS 冷启动答六问"语义等价、同样有效。

## 3. 新窗口验收（怎么算接手成功）

- 新窗口应**不翻旧聊天**就答出冷启动六问（①项目是什么/在采哪些平台与行业源；②四阶段走到哪、最近完成什么；③下一步与待拍板项+推荐；④开放问题/坑/数据缺口；⑤红线；⑥关键命令），清单原文见 `docs/项目维护SOP.md` §5。
- 老窗口可让新窗口把六问答出来，抽查 1~2 条与 `TASK_STATUS.md` 对得上。
- 答不上、或文档自相矛盾 → **不开工**，先按 `docs/项目维护SOP.md` 修文档（说明仓库自描述有缺口）。

## 4. 兜底（换机 / 网页版 / 无法选项目文件夹）

- **新 Mac 先 clone**：`git clone git@github.com:byte886/multiplatform-content-pipeline.git`，再把文件夹选成克隆目录，其余同 §2。
- 没法让系统读到项目 `AGENTS.md` 时，复制下面整段发给新窗口（已带仓库路径与阅读顺序）：

```

（GitHub: github.com/byte886/multiplatform-content-pipeline，public，master 分支）。

的解耦内容流水线，平台采集是个性插件、转写处理是公共层。

请严格按仓库根 AGENTS.md §1.1「冷启动」恢复，不要凭文件名猜测、不要直接写代码，按顺序读：
```

## 为什么至少还要"选文件夹 / 给路径"这一步

新对话默认不知道你要接手**哪个**项目（本机不止一个项目），所以"告诉它仓库在哪"省不掉——这本身就是"只需知道仓库位置"。位置一旦给了，**读什么、什么顺序、答哪六问、红线是什么，全部由仓库里的 AGENTS.md / 项目维护SOP / HANDOFF / 台账接管**；标准句再强制一次冷启动，不依赖自动注入是否生效，不需要解释任何来龙去脉。
