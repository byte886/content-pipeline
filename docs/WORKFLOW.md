## 整体流水线（七阶段版）

```
S0 任务定义与预判 → S1 采集 → S2 内容提取 → S3 视频/多媒体分析 → S4 最终文稿 → S5 知识化(OKF) → S6 质检迭代 → S7 云文档发布维护
   (G0 预判)      (多模态下载+评论+字幕) (转写/OCR/PDF/图文)   (按行业)       (成文)        (跨模态归并)    (机械门+复核)   (发布+维护)
```

| 阶段 | 目标 | 核心产出 | 校验门 |
|------|------|---------|--------|
| S0 任务定义与预判 | 按目标形态 / 素材类型 / 行业生成任务卡（G0） | 任务卡（manifest） | G0 字段齐、决策有依据 |
| S1 采集 | 多模态采集：视频 / 音频 / PDF / 图片 / 文本 / 图文 + 评论 + 字幕 | mp4、m4a、pdf、webp、txt、评论导出 | 数量对账、文件完整性、风控纪律 |
| S2 内容提取 | 转写 / OCR / PDF 解析 / 图文解析，产出一律转标准中间物 | transcript.md、OCR 文本、pdf 文本、图文元数据 | 转写覆盖率、空稿判定 |
| S3 视频/多媒体分析 | 判型命中后按行业做画面层 + 音频层分析 | 分析报告（路由 video-studio / OKF） | 判型表命中、产物路由正确 |
| S4 最终文稿 | 多源融合按作者角色成文（含双写决策 G4） | 最终文稿（06_articles） | 字数与时长相称、来源可溯 |
| S5 知识化（OKF） | 文稿 / 素材 → OKF 知识条目，G5 归并（含跨模态） | OKF bundle 更新 | okf_validate E0W0、对账零遗漏 |
| S6 质检迭代 | 机械门 + 人工复核 + 评估 Agent → 迭代 | 质检报告 | 全部检查门过（生成视频 / 发表前置） |
| S7 云文档发布维护 | 按守则放置 / 补 00_索引 / 残留过时重复维护 / 毕业 | 云文档更新 + 维护记录 | 00_索引已补、对账无残留 |

> 决策门 G0–G6 详设、多模态路由表、任务卡字段见 `docs/workflow/workflow-main.md`；四阶段（采集 / 处理 / 提取 / 组织）作为子环节在下文与 `docs/guides/` 详述。

## 阶段①：资源采集（S1 子环节，按平台分）

### 支持的平台
| 平台 | 采集方式 | 状态 | 详细SOP |
|------|---------|------|---------|
| 微信视频号 | MITM代理捕获URL → 下载解密 | ✅ 已跑通 | `wechat-channels-collect-sop.md` |
| B站 | 游客态翻页 + 直连限速 | ✅ 已接入 | `platforms/bilibili/` |
| 抖音 | 浏览器直读video流（绕过403） | ✅ 已跑通 | `platforms/douyin/README.md` |
| YouTube | 复用技能yt-dlp + 代理 | 🔧 待接入 | 技能内参考文档 |

### 采集子环节（通用）
1. **全量列表收集**：遍历作者主页，收集所有视频标题+URL，去重
2. **分类预判**：按标题自动分品类、价值等级、处理需求（是否要OCR/截图）
3. **状态清单生成**：Excel记录每个视频的下载/转写状态，作为增量更新基准
4. **批量下载**：按人类节奏（每5个歇30秒）防风控

### 校验门
- [ ] 全量视频数量与主页显示一致
- [ ] 状态清单已生成，含标题/URL/品类/价值等级/处理需求
- [ ] 已下载的视频文件可正常播放

---

## 阶段②：内容处理（通用能力）

### 通用处理流程
1. **语音转写**：FunASR本地离线转写 → 输出transcript.md
2. **智能关键帧抽取**：镜头检测+清晰度评分+dHash去重，自动挑最清晰的帧
3. **画面OCR**：macOS Vision识别画面上的文字（PPT/图表/参数）
4. **行业插件**：按行业自动加处理维度

### 校验门
- [ ] 所有已下载视频都有转写稿
- [ ] 教学类视频已跑OCR
- [ ] 实物展示类视频已截关键帧

- [ ] 跨视频相同观点已去重

## 阶段④：知识库组织与交付

### 子环节
1. **按行业组织**：股票/珠宝/创作分开存
2. **带图文档**：转写+OCR+关键帧合并成结构化md
3. **增量更新**：基于状态清单，只处理新增视频
4. **备份同步**：本地→网盘/飞书

### 校验门
- [ ] 知识库按行业组织完整
- [ ] 状态清单已更新（下载/转写/路径）
- [ ] 增量采集机制可用

---

## 增量采集（持续运营）
1. 重新拉全量列表 → 与状态清单对比 → 只处理新增
2. 新增视频走①→②→③→④完整流程
3. 更新状态清单和知识库

---

## 异常处理原则

1. **先怀疑AI自身**：端点、参数、ID、文件选取逻辑、最近改动（约九成问题在此）
2. **token/凭证问题最后怀疑**：须有只读请求返回登录超时的硬证据
3. **请求用户重新登录是最后手段**：不要一失败就让用户操作
4. **同一动作失败两次就换通道**：换命令、目录、依赖、实现路径
5. **网络阻断紧急恢复**：`pkill -9 -f video-capture` + 清除系统代理
