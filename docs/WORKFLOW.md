# 项目工作流（WORKFLOW）

> **文档类型**：Process（流程规范）
> **更新频率**：流程变更时
> **维护者**：AI自动维护 + 用户审核

> 本文档是项目的整体工作流，定义从采集到交付的四阶段流水线及各阶段校验门。

## 整体流水线

```
阶段① 资源采集 → 阶段② 内容处理 → 阶段③ 知识提取 → 阶段④ 知识库组织与交付
   (采集)          (处理)           (提取)            (交付)
```

| 阶段 | 目标 | 核心产出 | 校验门 |
|------|------|---------|--------|
| ① 资源采集 | 采集视频号和公众号的全部原始内容 | 短视频mp4、直播回放mp4、公众号文章JSON | 数量对账、文件完整性 |
| ② 内容处理 | 把音视频和图片变成可搜索的文字 | 转写稿md、文章正文+图片OCR | 转写覆盖率、OCR准确率 |
| ③ 知识提取 | 从文字中提取结构化投资知识 | 市场观点、技术点位、板块机会、书籍精华 | 提取完整性、去重 |
| ④ 知识库组织与交付 | 组织成可用的知识库并同步 | 知识库汇总、网盘备份 | 知识库可查询、网盘镜像一致 |

## 阶段①：资源采集

### 1.1 采集目标

| 类型 | 来源 | 采集方式 | 当前数量 |
|------|------|---------|---------|
| 短视频 | 视频号「交易的游戏」 | MITM代理捕获URL → 下载解密 | 313个 |
| 直播回放 | 视频号「交易的游戏」 | MITM代理捕获URL → 下载（无需解密） | 23个 |
| 公众号文章 | 公众号「顶底之王」 | 微信本地数据库读取 → 正文提取 | 277篇 |

### 1.2 子环节

1. **视频号URL捕获**：启动捕获工具 → 微信中打开视频号列表 → 滚动到底 → 停止捕获 → 输出URL清单
2. **视频下载**：批量下载短视频（自动解密）和直播回放（无需解密）
3. **公众号文章采集**：读取微信本地数据库 → 提取正文 → 下载图片

### 1.3 校验门（阶段完成标准）

- [ ] 短视频数量与视频号列表一致（去重后）
- [ ] 直播回放数量与视频号列表一致（去重后）
- [ ] 公众号文章数量与公众号列表一致
- [ ] 所有视频文件可正常播放（ffprobe验证）
- [ ] 所有文章有正文（无正文的记录原因）
- [ ] URL清单已保存到`workspace/capture/manifest/`

### 1.4 参考文档

- **微信基本操作SOP（前置依赖）**：`docs/SOP-wechat-basic-operations.md`（窗口管理、搜索操作、鼠标控制最佳实践）
- 视频号采集SOP：`docs/SOP-wechat-channels-capture.md`
- 公众号采集SOP：`docs/SOP-wechat-official-article.md`
- 高质量URL研究：`docs/RESEARCH-video-quality-url.md`
- 视频号API研究：`docs/RESEARCH-wechat-channels-api.md`

- [ ] 所有文章图片都有OCR结果（910张）
- [ ] OCR结果已更新到文章JSON中

## 阶段③：知识提取

### 3.1 子环节

1. **短视频知识提取**：从转写稿中提取市场观点、技术点位、板块机会
2. **公众号文章知识提取**：从正文中提取投资逻辑、个股分析、宏观判断
3. **书籍精华提取**：文章中推荐的书籍 → 查找书籍内容 → 形成文稿
4. **去重与合并**：跨内容的相同观点去重，相关观点合并

### 3.2 校验门（阶段完成标准）

- [ ] 所有转写稿都经过知识提取
- [ ] 所有文章都经过知识提取
- [ ] 提取结果无重复（同一观点不出现多次）
- [ ] 提取结果可追溯（标注来源视频/文章）

### 3.3 参考文档

- 知识提取工具：`processing/knowledge_extraction/tools/extract_knowledge.py`
- 知识库组织方案：`docs/DESIGN-knowledge-base-organization.md`

## 阶段④：知识库组织与交付

## 增量采集（持续运营）

当视频号或公众号有新内容时：

1. 重新捕获URL清单 → 与历史清单对比 → 只处理新增部分
2. 新增内容走阶段①→②→③完整流程
3. 更新知识库汇总

详见：`docs/SOP-wechat-channels-capture.md`「采集流程」章节

## 异常处理原则

1. **先怀疑AI自身**：端点、参数、ID、文件选取逻辑、最近改动（约九成问题在此）
2. **token/凭证问题最后怀疑**：须有只读请求返回登录超时的硬证据
3. **请求用户重新登录是最后手段**：不要一失败就让用户操作
4. **同一动作失败两次就换通道**：换命令、目录、依赖、实现路径
5. **网络阻断紧急恢复**：`pkill -9 -f video-capture` + 清除系统代理
