# ADR-002: 视频号采集的证书与代理方案

> **状态**：已采纳
> **日期**：2026-09-15
> **决策者**：AI + 用户

## 背景

微信视频号内容采集需要MITM代理捕获HTTPS流量。过程中遇到多次证书信任问题和代理设置问题，导致全网阻断。

## 决策

### 证书方案

1. **自签名CA证书**：使用goproxy生成的自签名CA证书，安装到系统钥匙串并信任
2. **证书位置**：`platforms/wechat_channels/video-capture/ca.crt`（与二进制同目录）
3. **证书加载**：使用相对于可执行文件的路径（`os.Executable()`），不使用相对路径或绝对路径
4. **信任设置**：`security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca.crt`

### 代理方案

1. **系统代理**：对所有活动网络服务（Ethernet、Wi-Fi等）同时设置HTTP/HTTPS代理
2. **代理端口**：默认9999（可配置）
3. **上游代理**：支持配置上游代理（默认ClashX 127.0.0.1:7890），国内流量直连、国外走VPN
4. **自动清理**：捕获工具退出时自动清除系统代理

### 运行规范

1. **必须从platforms/wechat_channels/video-capture/目录运行**，或使用start-capture.sh
2. **启动前检查**：项目根目录不应有ca.crt/ca.key（如果有说明运行目录错了）
3. **捕获完成后立即停止**，避免影响其他应用

## 踩坑记录

1. **只设置Wi-Fi代理**：微信走Ethernet，完全不走代理 → 必须对所有活动网络服务设代理
2. **相对路径加载证书**：从项目根目录运行时生成新的未信任证书 → 改用相对于可执行文件的路径
3. **证书信任设置为0**：`add-trusted-cert`有时不生效 → 需要用`-p ssl -p basic`显式指定策略
4. **ClashX横杠问题**：系统代理被捕获工具修改后，ClashX显示半选状态 → 捕获完成后清除代理即可恢复

## 紧急恢复

```bash
pkill -9 -f video-capture
for s in "Ethernet" "Wi-Fi"; do
  networksetup -setwebproxystate "$s" off
  networksetup -setsecurewebproxystate "$s" off
done
```

## 后果

### 正面
- 捕获工具可稳定运行，不再全网阻断
- 上游代理配置后，对其他应用影响很小
- 有明确的紧急恢复方案

### 负面
- 证书安装需要sudo权限
- 捕获期间系统代理被修改，可能影响其他应用（但上游代理缓解了这个问题）
