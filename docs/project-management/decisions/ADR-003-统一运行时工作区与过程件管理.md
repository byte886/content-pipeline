# ADR-003: 统一运行时工作区与过程件管理

> **状态**：已采纳
> **日期**：2026-09-15
> **决策者**：AI + 用户

## 背景

项目过程件（临时文件、日志、抓包数据、批次状态）散落在/tmp/和项目各处，缺乏统一管理。随着代码增多，需要一个集中的运行时工作区来管理过程件，避免污染项目目录和Git仓库。

参考高顿CPA项目的`data/_workspace/`设计（ADR-016），结合Python项目最佳实践，建立本项目的运行时工作区。

## 决策

### 工作区位置

`data/_workspace/` — 唯一运行时工作区，所有过程件集中管理。

### 目录结构

```
data/_workspace/
├── logs/          # 运行日志
├── tmp/           # 临时文件（用完即清）
└── capture/       # 采集相关（抓包数据、URL清单、批次状态）
```

### 核心规则

1. **所有过程件必须放在_workspace下**，不散落在项目根目录或tools/目录
2. **不入库、不传网盘、不同步飞书**：.gitignore已忽略data/目录
3. **分层清退**：tmp用完即清，capture短期保留，logs中期保留
4. **批次状态放在capture/下**，支持断点续传

### 与高顿项目的差异

高顿项目按账号级(_account/)和课程级(<course>/)分区，因为有多个课程和账号，过程件很多。
本项目只有一个采集目标，过程件相对较少，所以简化为3个子目录：logs、tmp、capture。
不完全生搬硬套高顿的6个子目录结构（run/tickets/manifest等），只保留真正需要的。

## 后果

### 正面
- 过程件集中管理，项目目录干净
- 大任务有检查点机制，支持异常恢复
- 分层清退避免磁盘占用过大
- 不污染Git仓库

### 负面
- 需要规范工具脚本的输出路径
- 旧脚本可能还在使用/tmp/，需要逐步迁移
