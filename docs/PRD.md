## 一、需求背景

### 1.1 问题陈述

作为A股投资者和内容创作者，面临以下痛点：

1. **信息碎片化**：视频号短视频、直播回放、公众号文章分散在不同平台，无法系统学习
2. **内容不可检索**：视频内容无法搜索，想回顾某个知识点只能重新刷视频
3. **缺乏知识沉淀**：看过的内容没有结构化整理，无法形成自己的投资体系
4. **量化素材缺失**：做量化系统需要大量策略灵感和验证素材，但零散内容难以利用
5. **创作效率低**：写公众号/做视频需要从零开始，没有素材库支撑

### 1.2 触发原因

- 关注了「交易的游戏」视频号（证券投资顾问，上海），内容质量高，有179个短视频+21个直播回放
- 关联公众号「顶底之王」有系统化图文内容
- 目标是构建自己的量化交易系统，同时运营自己的公众号/视频号

### 1.3 为什么现在做

- 视频号内容已全部下载解密，具备处理基础
- 微信本地数据库已解密，可自动化读取
- FunASR转写工具已验证可用
- 单人项目，时间灵活，适合长期建设

## 二、目标用户与场景

### 2.1 目标用户

**唯一用户：自己**

- 身份：A股投资者、量化系统开发者、内容创作者
- 技术能力：会Python、能操作命令行、有GitHub账号
- 使用场景：桌面端（Mac），非移动场景

### 2.2 核心使用场景

| 场景 | 频率 | 描述 |
|------|------|------|
| 知识学习 | 每日 | 按主题浏览视频号/公众号内容，系统学习投资知识 |
| 策略研发 | 每周 | 从知识库中提取交易策略，用于量化系统回测 |
| 内容创作 | 每周 | 基于素材库生成公众号文章/短视频脚本 |
| 知识点检索 | 随时 | 搜索某个技术指标/板块/策略的相关内容 |
| 新书学习 | 每月 | 从文章推荐中发现好书，整理书籍精华 |

## 三、产品目标与成功指标

### 3.1 产品目标

**短期目标（1个月内）**：
- 完成179个短视频+21个直播回放的转写和入库
- 实现公众号文章自动化采集
- 建立知识库目录结构和标签体系

**中期目标（3个月内）**：
- 完成至少50篇公众号文章的结构化整理
- 提取至少100个知识点（技术指标、策略、板块分析）
- 整理至少10本投资书籍精华
- 生成至少20套文案模板

**长期目标（6个月+）**：
- 知识库可支撑量化策略研发（至少5个策略从知识库中获得灵感）
- 可稳定产出公众号/视频号内容（每周至少2篇）
- 建立持续更新机制（自动跟踪新内容）

### 3.2 成功指标

|------|--------|----------|
| 视频转写完成率 | 100%（200个视频） | 转写文件数/总视频数 |

## 五、用户流程

### 5.1 内容采集流程

```
视频号/公众号发布新内容
    ↓
cron定时任务检测（每日2次）
    ↓
自动下载/抓取内容
    ↓
视频→FunASR转写 | 文章→正文提取+图片OCR
    ↓
AI结构化处理（分类、打标签、提取知识点）
    ↓
存入知识库对应目录
    ↓
更新索引和标签体系
```

### 5.2 知识检索流程

```
用户输入关键词（如"MACD底背离"）
    ↓
搜索知识库（文件名+内容+标签）
    ↓
返回相关视频转写/文章/知识点
    ↓
用户查看详情，可追溯到原始视频/文章
```

### 5.3 内容创作流程

```
用户选择创作类型（短视频/公众号/直播）
    ↓
选择主题（如"券商板块分析"）
    ↓
从知识库检索相关素材
    ↓
AI基于素材生成文案初稿
    ↓
用户编辑修改
    ↓
保存到文案素材库
```

## 六、核心需求详述

### 6.1 视频转写入库

**需求描述**：将已下载的179个短视频和21个直播回放全部转写为文字，按主题分类存入知识库。

**验收标准**：
- 所有视频都有对应的转写文字稿
- 转写准确率≥90%（财经术语正确）
- 每个视频都有标题、日期、时长、标签
- 按主题分类（午评/收评/板块/技术教学等）

**处理规则**：
- 短视频：保留完整转写，提取核心观点摘要
- 直播回放：按时间段分段，标注关键话题
- 统一命名格式：`YYYY-MM-DD_标题.md`

### 6.2 公众号文章自动化采集

**需求描述**：无需人工点击，自动获取「顶底之王」公众号的历史文章和新推送。

**验收标准**：
- 历史文章采集率≥90%
- 新文章推送后24小时内自动入库
- 文章正文完整提取（不含广告/无关内容）
- 文章中的图片自动OCR识别文字

**技术方案**：
- 方案A：微信UI自动化打开文章，等待缓存后读数据库
- 方案B：搜狗微信搜索获取URL，Chrome无头浏览器抓取
- 方案C：res-downloader抓包获取文章内容

### 6.3 知识库标签体系

**需求描述**：建立统一的标签体系，让视频号、公众号、书籍内容可以交叉关联。

**标签分类**：
- **技术指标**：MACD、KDJ、均线、成交量、布林带...
- **板块概念**：券商、科技、新能源、消费、医药...
- **交易策略**：趋势跟踪、均值回归、波段操作、打板...
- **宏观经济**：利率、汇率、通胀、政策...
- **市场状态**：牛市、熊市、震荡、底部、顶部...
- **投资理念**：价值投资、趋势投资、风险控制...

**验收标准**：
- 每条内容至少有2个标签
- 标签可检索，点击标签可看到所有相关内容
- 标签体系可扩展（新增标签不影响已有内容）

### 6.4 持续跟踪机制

**需求描述**：自动检测视频号和公众号的新内容，无需人工干预。

**验收标准**：
- 每日检测2次（早8点、晚8点）
- 新内容自动下载/抓取/转写/入库
- 失败时记录日志，可手动重试
- 不重复采集已入库内容

## 七、非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 单个视频转写≤实时时长的2倍；文章采集≤10秒/篇 |
| 可靠性 | 自动化任务失败率≤10%，有重试机制 |
| 可维护性 | 脚本有注释，配置集中管理，日志可追溯 |
| 扩展性 | 新增数据源/标签/分类不需要重构 |
| 数据安全 | 只采集公开内容，不存储个人隐私 |
| 成本 | 优先使用开源免费工具，控制API调用费用 |

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 微信版本升级导致数据库解密失败 | 中 | 高 | 关闭微信自动更新，锁定4.1.8版本 |
| 视频号反爬加强，抓包失效 | 中 | 高 | 多方案备份（UI自动化+第三方工具） |
| 公众号文章缓存机制变化 | 低 | 中 | 备用搜狗搜索+Chrome抓取方案 |
| 转写准确率低（财经术语） | 中 | 中 | 使用FunASR金融领域模型，人工抽检 |
| 单人项目精力不足，进度慢 | 高 | 中 | 优先级管理，MVP先行，逐步迭代 |
| 知识库内容越来越多，检索慢 | 低 | 中 | 后续接入向量数据库，提前规划索引 |
