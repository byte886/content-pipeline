### 工具选型边界（强制，禁止混用）
1.  **鼠标操作**（移动/悬停/点击/双击/滚动）：统一用`pyautogui`，底层封装Quartz原生事件，移动过程视觉可见可验证
2.  **窗口管理/系统快捷键**：统一用`AppleScript(osascript)`，比pyautogui发键更稳定
3.  **坐标定位**：必须用`screencapture -x -C`（带鼠标光标）全屏截图，每次操作前重新定位，**禁止使用历史写死坐标**
4.  ❌ 禁用`cliclick`：移动鼠标视觉不更新，无法验证悬停状态，已完全废弃
5.  ❌ 禁用macOS AX辅助树（Computer Use）操作微信：微信为自绘UI，AX树读不到内部元素

## 第1章 通用操作铁律（所有操作前必须遵守）

### 1.1 浮层与焦点清理
执行任何操作前，先连续按3次`ESC`关闭所有浮动弹窗（头像资料卡/下拉预览/右键菜单/网页查找条）；任何操作后立刻截图，弹出非预期浮层（表情选择/直播预约卡片）第一时间关闭，避免遮挡后续点击区域。
- 验证标准：顶部菜单栏左侧显示"微信"，否则所有快捷键失效
- 窗口结构认知：主窗口左侧「聊天/收藏/朋友圈」是视图切换，**不是独立窗口**，禁止用`Cmd+W`关闭；切回聊天视图按`Cmd+1`即可

### 1.2 UI定位标准流程（模拟人眼逻辑，禁止写死坐标）
所有鼠标操作完全模拟人用眼睛看屏幕找元素的方式，不依赖任何固定坐标：
1.  **全屏截图**：`screencapture -x -C /tmp/step.png`，带鼠标光标
2.  **OCR识别目标元素坐标**：从截图里识别目标文字/图标的实时屏幕坐标（如"搜索网络结果"行、"直播回放"标签），不写死任何固定x/y值
3.  **平滑移动鼠标**：`pyautogui.moveTo(识别到的坐标, duration=0.4)`，移动过程视觉可见
4.  **二次截图验证状态**：鼠标悬停后确认元素变灰/变手型/文字正确
5.  **确认无误再点击**，位置不对就重新截图识别，禁止凭经验盲算坐标

### 1.3 不同元素验证标准
| 元素类型 | 交互方式 | 验证通过标准 |
|---------|---------|-------------|
| 可点击条目/分类标签/菜单 | 悬停预览，无需提前点击 | ①鼠标变手型 ②元素变浅灰色高亮 ③元素文字/图标与目标完全一致 |
| 输入框 | 必须点击聚焦 | ①光标在输入框内 ②输入内容后出现下拉建议 |
| 视频缩略图 | 正式采集流程禁止点击（会打开播放页干扰流程） | — |

### 1.4 操作优先级
无视觉歧义的操作全部用快捷键；需要屏幕文字/图标/状态确认的操作，必须走"截图-定位-悬停-再截图验证"流程。

## 第2章 窗口管理

### 2.1 标准布局（任务开始时统一调整）
按优先级从左到右排布，横向空间不足再向下排布，窗口之间不重叠：
| 优先级 | 窗口 | 1920x1200参考位置 | 尺寸 |
|--------|------|-------------------|------|
| 1级 | 微信主窗口（聊天列表） | 左上角`(0,0)` | `900x600` |
| 2级 | 微信浏览器/搜一搜/视频号 | 主窗口右侧`(900,0)` | `1010x600` |
| 3级 | 其他（朋友圈等） | 主窗口下方`(0,600)` | `900x590` |

- **窗口识别必须用标题**，禁止用窗口索引（索引随开关变化不稳定）：主窗口标题为"微信"，浏览器窗口标题含"搜一搜"，朋友圈标题为"朋友圈"
- 布局完成后必须截图验证：两个窗口无重叠、完整显示无裁切，再开始操作
- 触发布局调整时机：任务开始、新窗口打开、窗口重叠遮挡

### 2.2 常用窗口操作
```bash
# 获取/设置窗口位置与大小
osascript -e 'tell application "System Events" to tell process "WeChat" to get position of window 1'
osascript -e 'tell application "System Events" to tell process "WeChat" to get size of window 1'

# 调整窗口
osascript <<'OSA'
tell application "System Events"
  tell process "WeChat"
    set size of window 1 to {900, 600}
    set position of window 1 to {0, 0}
  end tell
end tell
OSA
```

## 第3章 导航与搜索

### 3.1 主窗口导航快捷键
| 快捷键 | 功能 |
|--------|------|
| `Cmd+1` | 聊天视图 |
| `Cmd+2` | 通讯录 |
| `Cmd+3` | 收藏 |
| `Cmd+4` | 打开朋友圈新窗口 |

### 3.2 主窗口搜索完整流程（强制）
1.  标准激活前置流程（必须按顺序执行）：
    - 先`reopen`还原所有最小化窗口，再`activate`到前台
    - 按1次`ESC`关闭所有之前残留的错误浮层/小窗口
    - 按`Cmd+1`切回聊天视图
2.  按`Cmd+F`激活顶部搜索框，用`pbcopy`粘贴关键词
3.  滚动下拉列表定位目标：
    - 鼠标必须悬停在下拉列表**条目文字区域内**（不能在左侧空白栏），再执行`pyautogui.scroll(-10)`向下滚动；落在空白区域的滚轮事件微信不响应
    - 每滚动2-3次OCR识别一次，直到OCR**完全匹配6个汉字"搜索网络结果"**（红色星号前缀）
    - ❌ 禁止看到"搜索"两个字就停止！下拉列表里同时存在"搜索聊天记录"和"搜索网络结果"两个并列入口，模糊匹配100%误进聊天记录窗口
    - 确认完全匹配"搜索网络结果"后，**直接用OCR识别下方第一个目标条目的实时坐标，在该坐标点击**，不再用键盘↓数次数（本地结果数量动态变化，固定↓次数必然错位）
    - ❌ 禁止写死任何固定x坐标点击：下拉列表的水平范围与左侧导航栏完全重叠，窗口位置稍变就会点到导航图标上，必须用OCR返回的目标文字实时坐标
4.  进入搜一搜结果页后，悬停验证条目类型（条目下方必须有"视频号"灰色标签），确认类型正确再点击进入

> **常见坑点**：
> - 禁止写死按↓次数：本地结果（联系人/群聊/公众号/群聊消息）数量随聊天历史动态变化，固定次数100%误选
> - 滚动时鼠标必须落在条目文字区域内，落在列表左侧空白栏/窗口外时滚轮不生效
> - 禁止写死点击坐标：窗口位置/大小变化后，原固定坐标会点到左侧导航图标上
> - 同名条目必须按类型标签区分：同名公众号/视频号/服务号并排显示，禁止只按名称盲选第一个

### 3.3 微信浏览器（搜一搜/视频号窗口）操作
#### 搜索新内容
1.  按定位流程找到顶部搜索框（带"搜索账号"提示、右侧相机图标），点击聚焦
2.  输入关键词后直接按回车提交，不需要点绿色搜索按钮

#### 结果页操作
1.  必须先切到"全部"标签页，否则结果不完整
2.  按悬停标准验证条目：鼠标变手型、条目变灰、下方有对应类型标签
3.  多余标签页按`Cmd+W`关闭；只剩最后一个标签时按`Cmd+W`会关闭整个微信浏览器窗口

> **微信浏览器边界规则**：
> - `Cmd+F`是网页全局文字查找，**不是打开账号搜索框**，弹出的查找条ESC无法关闭，必须鼠标点×关闭
> - Tab键在微信浏览器内完全无效，不能用来切换到搜索框
> - `Cmd+A`是全选整个网页文字，禁止在非输入框状态下使用

## 第4章 特殊场景处理

### 4.1 带未开播预告的视频号
如果视频号主页存在"今天XX:XX直播"预告，鼠标移动经过预告文字热区会自动弹出右侧直播预约浮层，遮挡"直播回放"分类标签：
1.  优先用JS注入方式直接点击分类标签DOM元素，绕开鼠标悬停触发浮层的路径
2.  必须用鼠标操作时，从分类标签正下方垂直往上移动，路径保持在窗口最左侧边缘，避开中间预告热区
3.  浮层关闭×必须截图确认位置，禁止盲算坐标
4.  点击分类标签后必须截图确认标签高亮，再进行后续滚动采集

### 4.2 带付费生态的特殊视频号
如吴晓波频道类带付费音频课程的视频号，从搜一搜结果页直接双击条目会跳转付费课程页：
- 正确路径：先点同名公众号条目进入公众号详情页 → 点击详情页内"视频号"分类标签，直达视频号主页

## 第5章 常见问题速查
| 问题 | 解决方案 |
|------|---------|
| Tab键无反应 | 聊天输入状态下，按↓切换空白会话退出输入状态 |
| 键盘/点击无响应 | 检查窗口激活：顶部菜单栏显示"微信"，按钮为彩色 |
| Cmd+W关掉整个微信 | 仅在只剩主窗口时会发生，用`reopen`重开即可 |
| 中文输入失败 | 必须用`pbcopy`剪贴板粘贴，osascript原生不支持中文输入 |
| 截图看不到鼠标 | 截图命令加`-C`参数 |
| 搜索结果无视频号 | 停留在"划线"等其他标签页，切到"全部"标签 |
| 悬停标签不变灰 | 窗口未激活，先activate窗口再操作 |
| 点同名条目打开公众号/服务号 | 必须确认条目下方有"视频号"类型标签再点击 |
| 写死坐标永远点偏 | 窗口位置/大小每次变化，禁止使用历史固定坐标，每次重新截图定位 |

## 3.3 鼠标操作铁律（最高优先级）
1.  所有鼠标点击/悬停坐标**必须基于实时读取的微信主窗口实际位置动态计算**，绝对禁止写死任何绝对坐标。只要窗口位置/大小发生变化，写死坐标必然点到桌面或其他区域。
2.  每次操作前必须先用osascript读取微信主窗口的实际position和size，基于窗口左上角的相对偏移计算下拉列表、按钮、搜索框的绝对坐标，再执行点击。
3.  每一步操作前必须全屏截图验证元素状态（鼠标变成手型/条目变灰/文字匹配目标），确认无误后再点击。
4.  禁止在微信未激活、右侧聊天输入框处于输入状态时发送任何快捷键/鼠标点击。

## 3.4 微信窗口判别规则
微信进程下所有独立窗口类型：
| 窗口类型 | 是否保留 | 标题特征 |
|---|---|---|
| 微信主窗口 | ✅ 唯一保留 | 短标题，长度<10字符，以"微信"开头 |
| 朋友圈 | ❌ 子窗口，需关闭 | 独立弹出新窗口，长标题 |
| 公众号文章页 | ❌ 子窗口，需关闭 | 独立弹出新窗口，长标题，带文章/公众号名 |
| 视频号播放页 | ❌ 子窗口，需关闭 | 独立弹出新窗口，长标题 |
| 搜一搜结果页 | ❌ 子窗口，需关闭 | 独立弹出新窗口，长标题，带"搜一搜"字样 |

判别逻辑：遍历所有微信窗口，标题最短（长度<10、以"微信"开头）的就是主窗口，其余全部为子窗口，任务开始前/结束时全部关闭，只留主窗口。

## 3.4 主窗口判别最终方案（100%可靠）
**禁止再用窗口标题判断主窗口**：公众号/视频号等子窗口加载前，标题也会显示为"微信"，和主窗口完全一致，会误判。

✅ 唯一可靠判别方法：截图看左侧导航栏
- 主窗口：窗口最左侧一定有一竖排圆形导航图标（聊天/通讯录/收藏/朋友圈/视频号图标）
- 所有子窗口（公众号文章/朋友圈/视频号/搜一搜结果页）：窗口左侧没有这排竖排图标，直接就是网页/内容
判别流程：遍历所有微信窗口 → 对每个窗口截图 → 检查最左侧10%区域是否有竖排导航图标 → 有图标的才是主窗口，其余全部为子窗口需关闭
