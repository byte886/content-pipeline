# 视频资产台账规范（manifest）与价值评级 SOP

> 适用：content-pipeline 仓所有平台 / 账号采集的视频资产。
> 解决的问题：视频本体很大、不进 Git，换设备 / 云端 / 新会话 / 其他仓库的 Agent 就看不到
> "采了哪些、各自什么价值、文件在哪、是否重复"。本规范用「**大文件留本地，元数据入库**」
> 的方式，让资产清单成为跨设备可见、可版本回溯、可恢复的单一事实源。

---

## 1. 核心原则

1. **媒体本体不入库**：`*.mp4 / *.wav / *.m4a` 等大文件继续被 `.gitignore` 忽略，只存本机或网盘。
2. **元数据必须入库**：每个来源一份 `manifest.csv`（纯文本，可 git diff、可回溯），记录每条视频的身份、价值、采集状态、文件指纹与文稿位置。
3. **单一事实源分两层**：
   - `xlsx` 是本机富编辑工作副本（方便筛选、批量回写），**不入库**；
   - `manifest.csv` 是入库的权威快照，**由脚本从 xlsx 单向生成，禁止手改**。
   - 所有登记 / 评级 / 备注改动都在 xlsx 做，提交前重跑同步脚本刷新 manifest.csv。
4. **价值必须随资产一起记录**：每条视频都要有价值分级与（普通展示类的）A/B/C 评级及理由，做到"看见一条就知道为什么留它"。
5. **可恢复**：任何设备 clone 仓库后，凭 manifest 的 `url` 可重新下载视频，凭 `md5` 校验是否同一文件。

---

## 2. 文件职责

| 文件 | 位置 | 是否入库 | 职责 |
|---|---|---|---|
| 总清单 xlsx | `library/05_knowledge/<域>/<账号>/...总清单.xlsx` | 否（gitignore） | 本机富编辑源，15 列全量台账 |
| **manifest.csv** | `library/01_video/<一级>/<账号>/manifest.csv` | **是** | 入库权威快照，16 列，脚本生成 |
| 视频 mp4 | `library/01_video/<一级>/<账号>/*.mp4` | 否 | 原始视频，凭 url+md5 可重下 |
| 转写文稿 | `library/05_knowledge/<域>/<账号>/transcripts/<名>/transcript.md(+.json)` | 是（md/json） | 文字稿；json 提供时长 |
| 知识文档 | `library/05_knowledge/<域>/<账号>/*-知识文档.md` | 是 | 归并后的稳定知识成品 |

> `.gitignore` 已逐级放行 `library/01_video/` 目录，使 `manifest.csv / manifest.json / README.md`
> 能入库；目录放行后媒体文件仍被全局 `*.mp4` 等规则忽略，不会误纳。

## 3. manifest.csv 字段定义（固定 16 列，顺序不变）

| 列 | 含义 | 取值 / 来源 | 可空 |
|---|---|---|---|
| `vid` | 平台视频唯一 ID（抖音为 19 位纯数字字符串） | 从 `url` 提取，**不用** xlsx 里科学计数法的 vid 列 | 否，唯一 |
| `url` | 视频页地址 | xlsx `url` | 否 |
| `platform` | 平台 | douyin / xhs / bilibili / wechat_channels / youtube … | 否 |
| `account` | 来源账号 / 博主 | 如「珠宝学者郭颖」 | 否 |
| `title` | 干净标题（去前导编号与话题噪声后） | xlsx `title_clean`，空则回退 `title` | 否 |
| `category` | 品类 | xlsx `category`，如 翡翠/玉、其他 | 可空 |
| `value_level` | 价值分级（粗，见 §5） | 五档之一 | 否 |
| `review_grade` | 普通展示细筛档（见 §5） | A / B / C；非普通展示留空 | 可空 |
| `review_topic` | 复查建议归类 | 如 彩宝 / 翡翠 / 钻石 / 和田玉 … | 可空 |
| `downloaded` | 是否已下载 | 已下载 / 未下载 | 否 |
| `transcribed` | 是否已转写 | 已转写 / 未转写 | 否 |
| `media_relpath` | mp4 相对仓库根路径 | xlsx `local_path`；未下载留空 | 已下载必填 |
| `md5` | 视频文件 MD5 指纹 | 脚本扫描文件实算，用于重下校验与去重 | 已下载必填 |
| `duration_sec` | 时长（秒，一位小数） | 取自 `transcript.json` 的 `duration` | 已转写必填 |
| `transcript_relpath` | 转写文稿相对路径 | `transcripts/<名>/transcript.md` | 已转写必填 |
| `review_note` | 价值理由 + 同源重复主从 / 升降级说明 | xlsx `review_note`，追加不覆盖 | 可空 |

CSV 以 `utf-8-sig` 写出（Excel / Numbers 直接打开中文不乱码），字段内换行统一压成空格，保证一行一条记录、git diff 干净。

## 4. 日常维护流程

### 4.1 新增 / 补采一条视频
1. 按平台下载原片到 `library/01_video/<一级>/<账号>/`，转写到对应 `transcripts/`（走 `multiplatform-media-fetch` 技能）。
2. 在 xlsx 台账新增 / 更新该行：url、干净标题、品类、`value_level`、置「已下载 / 已转写」、填 `local_path`，普通展示类补 `review_grade / review_topic / review_note`。
3. 重跑同步脚本（见 §6），脚本自动补 md5、时长、文稿路径并对账。
4. 高价值 / A 类内容按归类并入对应《知识文档》。

### 4.2 修改评级或补备注
- 直接改 xlsx 的 `value_level / review_grade / review_topic`；
- 评级升降在 `review_note` **追加**「日期 + 结论 + 理由」，不要覆盖历史记录；
- 改完重跑脚本刷新 manifest。

### 4.3 提交前必做
- 重跑同步脚本，看到 `[对账通过]` 才允许提交；
- `git status` 确认本次只新增 / 修改 `manifest.csv`、脚本、文档，**没有**把 xlsx / mp4 / wav 带进暂存区。

### 4.4 跨设备 / 新会话恢复
- clone 仓库后直接读 `manifest.csv` 即掌握全部资产与价值，无需本机视频；
- 需要某条视频时按 `url` 重新下载到 `media_relpath`，再跑脚本，md5 与库内一致即证明是同一文件；不一致说明被替换 / 串流，需排查。

## 5. 价值评级标准

### 5.1 `value_level` 五档（内容性质，全量都要打）

| 档 | 定义 | 处置 |
|---|---|---|
| **高价值科普** | 系统的科普 / 鉴别 / 产地 / 分级 / 证书 / 避坑 / 工艺 / 原理 / 体系，标题即知识点，知识密度高 | 必采、必转写、必并入品类知识文档 |
| **潘家园实战** | 淘货 / 砍价 / 估价 / 逛展 / 行业生态等实战经验 | 必采，归《潘家园实战手册 / 分品类指南》 |
| **普通展示** | 高货审美、行情案例、名人品牌、文化寓意、开箱估价、原石品种展示等，知识密度中等 | 必须再做 A/B/C 细筛（§5.2） |
| **节日/水视频** | 节日借势、经典歌曲搬运、与主题无关的凑数内容 | 放弃，不下载 |
| **广告/活动** | 直播预告、招生、公益颁奖、展会招募、纯带货活动 | 放弃，不下载 |

### 5.2 `review_grade` A/B/C（仅对「普通展示」逐条细筛）

判定依据：**视频标题 + 话题标签 + 所属品类**做语义判定（标题直白、信息完整时可靠）；A 类以"下载转写"作为内容验证，名不副实即降级。

| 档 | 含义 | 判定特征 | 处置 |
|---|---|---|---|
| **A** | 建议补采 | 明确的科普 / 鉴别 / 产地 / 分级 / 证书 / 避坑 / 工艺 / 原理 / 体系 / 行情，标题即知识点 | 下载→转写（转写即验证）→并入对应品类文档 |
| **B** | 可选、留档 | 拍卖高货 / 名人珠宝 / 品牌故事 / 文化寓意 / 开箱估价 / 原石展示，以审美与行情参考为主，知识密度中等 | 暂不采；做高货审美、行情案例、文化故事、**视频创作对标**时按单取用 |
| **C** | 不采 | 经典歌曲、节日借势、招生 / 公益 / 颁奖 / 展会、纯互动带货、个人 vlog、与已采内容重复 | 放弃，不下载 |

> B 档对"提炼知识"价值有限，但对"短视频创作对标"价值高（流量 / 种草 / 转化范式）。
> 取用 B 档做创作参考时，走视频效果分析 SOP 拆钩子 / 分镜 / 光影 / 音频 / 提示词，
> **只借鉴结构与镜头语言，成片用 AI 重新生成、拍自己的货，不搬运原片画面与文案**。

### 5.3 升降级规则
- B 档下载转写后证实为系统知识点 → 升 A（改 `review_grade`，必要时调 `value_level`，补归类，并入文档）。
- A 档转写后发现名不副实 → 降 B 或 C。
- 任何升降级都在 `review_note` 追加「日期 + 变更 + 理由」，保留轨迹。

## 6. 同步 / 对账脚本

脚本：`scripts/xlsx_to_manifest.py`（纯标准库 + openpyxl，幂等，可重复运行）。

```bash
python3 scripts/xlsx_to_manifest.py \
  --xlsx "library/05_knowledge/jewelry/珠宝学者郭颖/郭颖珠宝视频知识库_总清单.xlsx" \
  --video-dir "library/01_video/jewelry/珠宝学者郭颖" \
  --transcript-dir "library/05_knowledge/jewelry/珠宝学者郭颖/transcripts" \
  --out "library/01_video/jewelry/珠宝学者郭颖/manifest.csv" \
  --platform douyin --account "珠宝学者郭颖"
```

脚本会：从 url 提取 19 位 vid；扫描 mp4 实算 md5；从 `transcript.json` 读时长；回填文稿路径；
打印总数、价值分级 / 评级分布、下载 / 转写 / md5 / 时长 / 文稿计数。

以下硬异常会以非零码退出（对账失败，不得提交）：
- 已下载但缺 `local_path` 或文件不存在；未下载却填了路径；
- 已转写但缺 `transcript.md` 或 `transcript.json` 读不出时长；
- vid 缺失、不为 19 位数字或重复；
- 视频目录里有 mp4 但台账未登记（防漏登）。

md5 出现重复只**告警**不判失败：已知存在博主"同文件一稿两发"（如帝王绿），这类在
`review_note` 标注主从，文件保留不删。

## 7. 新增一个来源 / 平台

1. 目录约定两级：`library/01_video/<一级>/<账号>/`，第二级为账号；第一级用平台名
   （douyin / xhs / bilibili …）或内容大类（如已有的 `jewelry`），全库尽量统一、同一来源保持一致。
2. 在该目录放 `manifest.csv`（列定义与 §3 完全一致）；`.gitignore` 已放行两级目录下的
   `manifest.csv / manifest.json / README.md`，无需再改忽略规则。
3. 有 xlsx 的来源照 §6 传不同路径参数生成；没有 xlsx 的来源可直接维护 manifest.csv（此时它就是一手源），但列与取值口径不变。
4. 在 `library/01_video/README.md` 顶层索引登记该来源（路径、平台、账号、条数、状态）。

---

## 8. 与其他资产 / 仓库的边界

- **源视频、转写、本 manifest**：留在 content-pipeline（采集加工仓）。
- **稳定知识成品**：归并后的《知识文档》在 `library/05_knowledge/`，入库。
- **视频创作对标卡片**（B 档等高货 / 故事类拆出的钩子、分镜、光影、BGM/音效、可复用提示词）：
  归 video-studio 仓的创作对标库；源素材与转写仍以本仓 manifest 为索引，不重复搬大文件。
