## 1. 项目背景与目标

### 1.1 背景

用户是A股投资者、量化系统开发者、内容创作者，关注多个平台的优质内容（微信公众号/视频号/B站/抖音/YouTube），这些内容包含大量有价值的投资观点、技术分析、行业知识、创作方法，但存在以下问题：

- **内容分散**：视频、图文、直播分散在不同平台，无法系统学习
- **不可检索**：视频内容无法搜索，想回顾某个知识点只能重新播放
- **缺乏沉淀**：看过的内容没有结构化整理，无法形成自己的知识体系
- **量化素材缺失**：做量化系统需要大量策略灵感和验证素材，但零散内容难以利用
- **创作效率低**：写公众号/做视频需要从零开始，没有素材库支撑
- **方法难复制**：看到优秀博主的拍摄技巧、AI使用、内容呈现，难以提炼复用

### 1.2 核心诉求（一句话）

**构建多平台内容采集与知识库生成框架，自动化采集各平台的视频和图文，经过转写/OCR/知识提取后形成结构化知识库，并支持按行业（股票/珠宝等）生成文稿和视频，同时支持方法提炼（分析博主创作方法，提炼可复用的生成方法）。**

### 1.3 最终目标

用户最终获得：

1. **一个完整的内容存档** — 所有短视频、直播回放、公众号文章保存在本地和网盘，永久可访问
2. **一个可搜索的知识库** — 视频里讲的、文章里写的、图片里画的，全部变成文字，按主题组织，随时搜得到
3. **一个持续更新的跟踪系统** — 可以方便地采集新内容，增量更新知识库
4. **一个量化系统的数据基础** — 结构化的市场观点、技术点位、板块机会，可用于量化分析
5. **一个内容创作的素材库** — 可基于知识库生成公众号文章和短视频文案
6. **一个方法提炼库** — 分析优秀博主的创作方法，提炼可复用的拍摄/AI/内容呈现技巧

### 1.4 目标用户

**唯一用户：自己**

- 身份：A股投资者、量化系统开发者、内容创作者
- 技术能力：会Python、能操作命令行、有GitHub账号
- 使用场景：桌面端（Mac），非移动场景

## 2. 核心功能需求

### 2.1 多平台自动化采集系统

#### 2.1.1 平台插件化架构

- **需求**：支持多平台采集，新平台接入只需实现统一接口
- **实现方式**：
  - `platforms/base.py` 定义 `PlatformFetcher` 统一接口
  - 各平台独立实现（wechat_official/wechat_channels/bilibili/douyin/youtube）
  - `config/sources.json` 配置驱动（平台→账号→行业映射）
- **验收标准**：新平台接入不需要修改主流程代码

#### 2.1.2 微信视频号采集（已完成）

- **需求**：自动化采集视频号的全部短视频和直播回放
- **实现方式**：
  - MITM代理捕获视频URL（自研Go工具，参考RES Downloader）
  - 微信中打开视频号列表 → 滚动到底 → 自动捕获所有URL
  - 批量下载（短视频需ISAAC64解密，直播回放无需解密）
  - 支持增量采集（水位机制，只采集新内容）
- **已采集**：313个短视频（1.6GB）+ 23个直播回放（4.9GB）
- **验收标准**：能采集到视频号的全部内容，文件可正常播放

#### 2.1.3 微信公众号采集（已完成）

- **需求**：自动化采集公众号的全部文章
- **实现方式**：
  - 读取微信本地数据库（wx-cli技能）
  - 提取文章正文和图片
  - 图片OCR识别（macOS Vision，编译二进制提速10倍）
- **已采集**：277篇文章（275篇有正文，910张图片已OCR）
- **验收标准**：能采集到公众号的全部文章，正文完整，图片有OCR结果

#### 2.1.4 B站采集（待接入）

- **需求**：采集B站UP主的全部视频
- **实现方式**：复用珠宝项目的bili_list.py、collect_seasons.py等脚本（wbi签名+合集采集）
- **参考**：珠宝知识库项目已采集B站UP「宝石学家老许」743个视频
- **验收标准**：能采集到指定UP主的全部视频和转写稿

#### 2.1.5 抖音/YouTube采集（待接入）

- **需求**：采集抖音/YouTube博主的视频
- **实现方式**：复用multiplatform-media-fetch技能的media_downloader.py（yt-dlp封装）
- **验收标准**：能采集到指定博主的视频

#### 2.1.6 断点续传与异常恢复

- **需求**：采集中断后可以从断点继续，不重复已完成工作
- **实现方式**：
  - URL清单保存到`workspace/capture/manifest/`
  - 下载状态记录（已下载/未下载/下载失败）
  - 异常中断后从状态文件恢复
- **验收标准**：中断后重新运行，能从断点继续

### 2.2 公共内容处理系统

#### 2.2.1 视频转文字

- **需求**：把所有视频（短视频和直播回放）转成文字稿
- **实现方式**：FunASR本地离线转写（SenseVoiceSmall模型，9.7x实时）
- **已完成**：313个短视频全部转写
- **待完成**：23个直播回放转写（每个1-3小时）
- **验收标准**：所有视频都有对应的转写稿，转写稿非空、无明显乱码

#### 2.2.2 图文OCR

- **需求**：公众号文章中的图片（图表、K线图）需要OCR识别
- **实现方式**：macOS Vision框架（编译为二进制，1.5秒/张）
- **已完成**：910张图片OCR，更新236篇文章
- **验收标准**：所有文章图片都有OCR结果，OCR结果已更新到文章JSON中

#### 2.2.3 视频解密（视频号特有）

- **需求**：短视频下载后是加密的，需要解密才能播放
- **实现方式**：ISAAC64解密（详细原理见 `docs/SOP-wechat-channels-capture.md` §2.2）
- **验收标准**：解密后的视频可正常播放

#### 2.2.4 内容标准化/去重

- **需求**：各平台内容转换为统一格式，去重
- **实现方式**：`processing/normalization/`（待实现）
- **验收标准**：不同平台的内容可以统一处理和查询

### 2.3 知识提取系统

#### 2.3.1 结构化知识提取

- **需求**：从转写稿和文章中提取结构化知识
- **提取维度**（按行业定制）：
  - 股票行业：市场观点、技术点位、板块机会、个股研究、宏观策略
  - 珠宝行业：宝石学知识、鉴定方法、市场趋势、选购指南
  - 通用：核心观点、关键数据、引用来源
- **验收标准**：提取结果可追溯（标注来源），无重复

#### 2.3.2 书籍精华提取

- **需求**：文章中推荐的书籍，需要查找书籍内容形成文稿
- **实现方式**：根据书名查找书籍内容 → 提取精华 → 形成文稿
- **验收标准**：推荐的书籍都有对应的精华文稿

#### 2.3.3 方法提炼（MethodNote，新增需求）

- **需求**：分析优秀博主的拍摄技巧、AI使用、内容呈现，提炼可复用的生成方法
- **场景**：看到一个抖音广告博主，拍摄技巧、AI使用效果、内容呈现都很新颖
- **目标**：不是进入该行业，而是提炼方法，方便抄袭风格和生成视频
- **提取维度**：
  - 拍摄技巧（镜头、运镜、布光）
  - AI工具使用（哪些AI工具、怎么用）
  - 内容结构（开头/主体/结尾的组织方式）
  - 视觉风格（色调、构图、字幕样式）
  - 音频风格（配音、背景音乐、音效）
  - 节奏控制（剪辑节奏、信息密度）
  - 分步生成方法（可复现的生成步骤）
- **输出**：`library/05_knowledge/concepts/methods/` 下的MethodNote
- **验收标准**：每个方法笔记包含可操作的生成步骤，能指导实际创作

### 2.4 多行业知识库组织与交付

#### 2.4.1 行业隔离

- **需求**：不同行业（股票/珠宝）有独立的知识库、文章撰写模板、审稿规则
- **实现方式**：`domains/stock/`、`domains/jewelry/` 各有独立目录
- **验收标准**：各行业内容互不干扰，可独立扩展

#### 2.4.2 知识库组织

- **需求**：按主题组织提取的知识，形成可用的知识库
- **组织方式**（OKF v0.2格式）：
  - `concepts/videos/` — 视频笔记（VideoNote）
  - `concepts/articles/` — 图文笔记（ArticleNote）
  - `concepts/books/` — 书籍笔记（BookNote）
  - `concepts/reports/` — 报告笔记（ReportNote）
  - `concepts/methods/` — 方法笔记（MethodNote）
  - `concepts/topics/` — 主题融合页
- **验收标准**：知识库按主题组织完整，可通过工具查询

#### 2.4.3 文章撰写与审稿

- **需求**：基于知识库生成行业文稿，并按行业规则审稿
- **实现方式**：`domains/<行业>/article_writer/` + `article_reviewer/`
- **验收标准**：生成的文稿符合行业规范，审稿规则可执行

#### 2.4.4 多端同步

- **需求**：本地数据同步到百度网盘，跨设备访问
- **实现方式**：百度网盘API同步脚本（`scripts/netdisk/`）
- **验收标准**：百度网盘与本地数据镜像一致

#### 2.4.5 增量更新机制

- **需求**：跟踪新内容，只采集和处理新增部分
- **实现方式**：水位（watermark）机制，先成功落地再推进水位
- **验收标准**：增量采集机制可用，不重复处理已有内容

## 5. 用户流程

### 5.1 内容采集流程

```
各平台发布新内容
    ↓
水位机制检测（增量采集）
    ↓
平台Fetcher自动下载/抓取内容
    ↓
视频→解密→FunASR转写 | 文章→正文提取+图片OCR
    ↓
AI结构化处理（分类、打标签、提取知识点/方法）
    ↓
存入library/对应目录
    ↓
更新水位和索引
```

### 5.2 知识检索流程

```
用户输入关键词（如"MACD底背离"）
    ↓
搜索知识库（文件名+内容+标签）
    ↓
返回相关视频转写/文章/知识点/方法笔记
    ↓
用户查看详情，可追溯到原始视频/文章
```

### 5.3 内容创作流程

```
用户选择创作类型（短视频/公众号/直播）
    ↓
选择行业和主题
    ↓
从知识库检索相关素材+方法笔记
    ↓
AI基于素材和方法生成文案初稿
    ↓
用户编辑修改
    ↓
保存到文案素材库
```

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 单个视频转写≤实时时长的2倍；文章采集≤10秒/篇 |
| 可靠性 | 自动化任务失败率≤10%，有重试机制 |
| 可维护性 | 代码按功能分目录组织，每个工具有README或SOP说明 |
| 扩展性 | 新增平台/行业/标签不需要重构（插件化架构） |
| 数据安全 | 只采集公开内容，不存储个人隐私，密钥加密存储 |
| 成本 | 优先使用开源免费工具，控制API调用费用 |
| 自动化 | 用户不在电脑旁时也能运行（后台任务） |
| 可追溯 | 每条知识都能追溯到原始视频/文章和处理步骤 |

## 9. 需求处理原则

1. **一次一问**：复杂需求先拆解，逐个确认
2. **先给推荐**：AI先给出推荐方案，用户确认后执行
3. **稳定结论单向流动**：需求确认后，稳定结论写入ADR/工程记忆，过程件只放指针
4. **问题驱动更新**：发现问题立即评估是否需要更新需求或文档
5. **单一权威源**：每个主题只有一个权威文档，其他文档只链接不复制
