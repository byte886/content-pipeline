## 1. 项目背景与目标

### 1.1 背景

用户关注A股投资，关注公众号「顶底之王」和关联视频号「交易的游戏」（证券投资顾问刘广义）。这些内容包含大量有价值的投资观点、技术分析、板块机会，但存在以下问题：

- 视频号内容无法搜索，复习时需要从头播放
- 直播回放时间长（1-3小时），关键观点难以快速定位
- 公众号文章和视频内容分散，难以系统整理
- 文章中的图片（图表、K线图）无法被搜索
- 有时会推荐好书，但书籍内容需要单独查找
- 需要一个自动化系统来持续跟踪和整理这些内容

### 1.2 核心诉求（一句话）

**通过自动化采集公众号和视频号的全部内容，构建一个可搜索、可追溯的A股投资知识库，为量化系统和内容创作提供数据基础。**

### 1.3 最终目标

用户最终获得：

1. **一个完整的内容存档** — 所有短视频、直播回放、公众号文章保存在本地和U盘/网盘，永久可访问
2. **一个可搜索的投资知识库** — 视频里讲的、文章里写的、图片里画的，全部变成文字，按主题组织，随时搜得到
3. **一个持续更新的跟踪系统** — 可以方便地采集新内容，增量更新知识库
4. **一个量化系统的数据基础** — 结构化的市场观点、技术点位、板块机会，可用于量化分析
5. **一个内容创作的素材库** — 可基于知识库生成公众号文章和短视频文案

## 2. 核心功能需求

### 2.1 自动化采集系统

#### 2.1.1 视频号内容采集

- **需求**：自动化采集视频号「交易的游戏」的全部短视频和直播回放
- **实现方式**：
  - MITM代理捕获视频URL（自研工具，参考RES Downloader）
  - 微信中打开视频号列表 → 滚动到底 → 自动捕获所有URL
  - 批量下载（短视频需解密，直播回放无需解密）
  - 支持增量采集（只采集新内容）
- **验收标准**：能采集到视频号的全部短视频和直播回放，文件可正常播放

#### 2.1.2 公众号文章采集

- **需求**：自动化采集公众号「顶底之王」的全部文章
- **实现方式**：
  - 读取微信本地数据库（wx-cli）
  - 提取文章正文和图片
  - 图片OCR识别（macOS Vision）
- **验收标准**：能采集到公众号的全部文章，正文完整，图片有OCR结果

#### 2.1.3 断点续传与异常恢复

- **需求**：采集中断后可以从断点继续，不重复已完成工作
- **实现方式**：
  - URL清单保存到`data/_workspace/capture/manifest/`
  - 下载状态记录（已下载/未下载/下载失败）
  - 异常中断后从状态文件恢复
- **验收标准**：中断后重新运行，能从断点继续

### 2.2 内容处理系统

#### 2.2.1 视频转文字

- **需求**：把所有视频（短视频和直播回放）转成文字稿
- **实现方式**：FunASR本地离线转写（SenseVoiceSmall模型）
- **验收标准**：所有视频都有对应的转写稿，转写稿非空、无明显乱码

#### 2.2.2 图文OCR

- **需求**：公众号文章中的图片（图表、K线图）需要OCR识别
- **实现方式**：macOS Vision框架（编译为二进制提速10倍）
- **验收标准**：所有文章图片都有OCR结果，OCR结果已更新到文章JSON中

#### 2.2.3 视频解密

- **需求**：短视频下载后是加密的，需要解密才能播放
- **实现方式**：DecodeKey → ISAAC64生成128KB数组 → XOR文件前128KB
- **验收标准**：解密后的视频可正常播放

### 2.3 知识提取系统

#### 2.3.1 结构化知识提取

- **需求**：从转写稿和文章中提取结构化的投资知识
- **提取维度**：
  - 市场观点（大盘判断、多空观点）
  - 技术点位（支撑位、压力位、关键指数点位）
  - 板块机会（行业分析、热点板块）
  - 个股研究（具体股票分析）
  - 宏观策略（政策解读、宏观经济）
- **验收标准**：提取结果可追溯（标注来源），无重复

#### 2.3.2 书籍精华提取

- **需求**：文章中推荐的书籍，需要查找书籍内容形成文稿
- **实现方式**：根据书名查找书籍内容 → 提取精华 → 形成文稿
- **验收标准**：推荐的书籍都有对应的精华文稿

### 2.4 知识库组织与交付

#### 2.4.1 知识库组织

- **需求**：按主题组织提取的知识，形成可用的知识库
- **组织方式**：
  - 01-视频号内容（短视频转写稿、直播回放转写稿）
  - 02-公众号文章（正文+图片OCR）
  - 03-书籍精华
  - 04-知识点图谱（结构化投资知识）
  - 05-文案素材库（可用于内容创作）
- **验收标准**：知识库按主题组织完整，可通过工具查询

#### 2.4.2 多端同步

- **需求**：本地数据同步到百度网盘（股票知识库应用），跨设备访问
- **实现方式**：百度网盘API同步脚本
- **验收标准**：百度网盘与本地数据镜像一致

#### 2.4.3 增量更新机制

- **需求**：跟踪新内容，只采集和处理新增部分
- **实现方式**：URL清单对比 → 只处理新增 → 更新知识库
- **验收标准**：增量采集机制可用，不重复处理已有内容

## 3. 非功能需求

### 3.1 自动化程度

- 采集过程尽量自动化，减少人工干预
- 微信登录等敏感操作可由用户协助
- 用户不在电脑旁时也能运行（后台任务）

### 3.2 数据安全

- 不触发微信风控（不频繁请求、不模拟异常行为）
- 采集的内容仅供个人学习使用，不传播
- 密钥和凭证安全存储

### 3.3 可维护性

- 代码按功能分目录组织
- 每个工具有README或SOP说明
- 文档与代码同步更新

### 3.4 性能

- 视频下载支持多线程
- 转写支持批量处理
- OCR编译为二进制提速

## 4. 已关闭 / 被取代的方案（留痕）

| ID | 原方案 | 关闭原因 |
|----|--------|----------|
| X-01 | RES Downloader作为主力采集工具 | 已自研捕获工具替代，不依赖第三方应用 |
| X-02 | 只设置Wi-Fi代理 | 微信走Ethernet，完全不走代理 → 改为对所有活动网络服务设代理 |
| X-03 | tcpdump/Wireshark底层抓包 | HTTPS加密无法直接解析，MITM代理更合适 |
| X-04 | 高质量URL只保留encfilekey+token参数 | 下载0字节，必须保留完整参数 |
| X-05 | 从项目根目录运行捕获工具（旧版） | 相对路径加载证书导致生成未信任新证书 → 已修复为相对于可执行文件的路径 |

## 5. 需求处理原则

1. **一次一问**：复杂需求先拆解，逐个确认
2. **先给推荐**：AI先给出推荐方案，用户确认后执行
3. **稳定结论单向流动**：需求确认后，稳定结论写入ADR/工程记忆，过程件只放指针
4. **问题驱动更新**：发现问题立即评估是否需要更新需求或文档
