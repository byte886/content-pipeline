# 项目需求文档（REQUIREMENTS）

> **文档类型**：Concept（概念说明 — 需求文档）
> **更新频率**：需求变更时
> **维护者**：AI自动维护 + 用户审核

---

## 1. 项目目标

**构建多平台内容采集与知识库生成框架**：自动化采集各平台视频和图文，经过转写/OCR/知识提取后形成结构化知识库，支持按行业生成文稿和视频，同时支持方法提炼。

**最终交付**：
1. 完整的内容存档（本地+网盘）
2. 可搜索的结构化知识库
3. 持续更新的跟踪系统
4. 量化系统的数据基础
5. 内容创作的素材库
6. 方法提炼库（分析优秀博主的创作方法）

---

## 2. 核心功能需求

### 2.1 多平台自动化采集

| 平台 | 状态 | 实现方式 |
|------|------|---------|
| 微信视频号 | ✅ 已完成 | MITM代理捕获URL + 批量下载解密 |
| 微信公众号 | ✅ 已完成 | 读取本地数据库 + 正文提取 + 图片OCR |
| B站 | ⏳ 待接入 | 复用珠宝项目bili_list.py（wbi签名） |
| 抖音/YouTube | ⏳ 待接入 | 复用multiplatform-media-fetch技能 |

**架构要求**：插件化，新平台接入只需实现统一接口（`PlatformFetcher`），配置驱动（`config/sources.json`）。

### 2.2 公共内容处理

| 功能 | 状态 | 实现方式 |
|------|------|---------|
| 视频转文字 | ✅ 短视频完成，直播待转写 | FunASR本地离线（SenseVoiceSmall） |
| 图文OCR | ✅ 已完成 | macOS Vision（编译二进制，1.5秒/张） |
| 视频解密 | ✅ 已完成 | ISAAC64解密（视频号短视频特有） |
| 内容去重 | ⏳ 待实现 | 统一格式，按唯一键去重 |

### 2.3 知识提取

- **结构化知识提取**：从转写稿和文章中提取知识点（股票/珠宝行业定制维度）
- **书籍精华提取**：文章中推荐的书籍，查找电子版并提取精华
- **方法提炼（MethodNote）**：分析优秀博主的拍摄技巧、AI使用、内容呈现，提炼可复用的生成方法

### 2.4 多行业知识库

- **行业隔离**：不同行业（股票/珠宝）有独立的知识库和模板
- **知识库组织**：OKF v0.2格式，按主题组织（视频笔记/图文笔记/书籍笔记/方法笔记）
- **文章撰写与审稿**：基于知识库生成行业文稿，按行业规则审稿
- **多端同步**：百度网盘API同步
- **增量更新**：水位机制，只处理新增部分

## 3. 功能范围

### MVP（v1.0，已完成）
- 微信视频号/公众号采集
- 短视频转写 + 图文OCR
- 多平台架构重构

### v1.1（进行中）
- 直播回放转写
- B站采集接入
- 知识提取批量运行
- 方法提炼框架

### v2.0（未来）
- 抖音/YouTube采集
- 向量检索（语义搜索）
- 量化策略对接
- 文章撰写与审稿
- Web界面 + AI问答

### 明确不做（Non-Goals）
- ❌ 不做实盘交易
- ❌ 不做移动端App
- ❌ 不做用户系统（单人项目）
- ❌ 不做付费内容采集
- ❌ 不做企业级微服务（保持轻量）

## 4. 风险与应对

| 风险 | 应对措施 |
|------|---------|
| 微信版本升级导致解密失败 | 锁定4.1.8版本，关闭自动更新 |
| 视频号反爬加强 | 多方案备份（UI自动化+第三方工具） |
| 转写准确率低（专业术语） | 使用领域模型，人工抽检 |
| 单人项目精力不足 | MVP先行，优先级管理，逐步迭代 |
| 多平台扩展导致架构复杂 | 严格插件化，平台间不耦合 |
