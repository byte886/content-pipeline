## 一、项目演进历程

### 1.1 项目起源

源于验证需求：**验证微信公众号视频下载方法**。测试目标：视频号「交易的游戏」（关联公众号「顶底之王」）。

工具尝试路径：RES Downloader → ClashX代理 → tcpdump/Wireshark（HTTPS加密不可行）→ 自研Go MITM捕获工具。

### 1.2 发展阶段

| 阶段 | 时间 | 核心内容 |
|------|------|----------|
| 阶段1：下载验证 | 2026-09初 | 自研MITM捕获工具，证书路径修复 |
| 阶段2：全量采集 | 2026-09中 | 视频号+公众号全量采集 |
| 阶段3：内容处理 | 2026-09中 | 视频转写+图文OCR |
| 阶段4：项目治理 | 2026-09中 | 参考高顿项目建立治理体系 |
| 阶段5：架构重构 | 2026-09-15 | 单一股票知识库→多平台多行业框架 |

## 三、经验教训

### 3.1 技术层面

| 教训 | 结论 |
|------|------|
| 证书相对路径导致全网阻断 | 证书用`os.Executable()`相对路径，与二进制同目录 |
| tcpdump/Wireshark抓HTTPS | 必须MITM代理，安装自签名证书 |
| 全局代理影响所有程序 | 自研MITM工具支持上游代理，只拦截微信流量 |
| B站wbi签名412风控 | 双通道设计，wbi首选、dynamic备用，Chrome cookie修复 |

### 3.2 项目管理层面

| 教训 | 结论 |
|------|------|
| 无文档导致AI遗忘 | 建立完整文档治理体系，重要决策记录到ADR |
| 从零设计易走弯路 | 深度研究高顿CPA和珠宝项目，吸收成熟经验 |
| 迭代积累冗余 | 定期计划性评审，全量精读MD文件 |
| 批量改名易断引用 | L1高扩散变更先出方案+影响清单，用户确认后执行 |

### 3.3 协作层面

| 教训 | 结论 |
|------|------|
| 反复犯同样错误 | 用户偏好记录到AGENTS.md |
| 阻塞时用户不知道 | 遇到微信锁定等需用户操作的场景及时通知 |
