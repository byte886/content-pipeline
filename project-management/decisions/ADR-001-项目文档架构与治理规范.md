# ADR-001: 项目文档架构与治理规范

> **状态**：已采纳
> **日期**：2026-09-15
> **决策者**：AI + 用户

## 背景

项目工具多、目录乱，缺少统一的文档架构和治理规范。参考高顿CPA课程知识库项目的成熟架构，建立本项目的文档治理体系。

## 决策

采用高顿项目的文档分层架构，结合本项目特点简化：

### 文档分层

```
根目录/
├── README.md              # 项目概览（给人看）
├── AGENTS.md              # AI操作手册（给AI看，命令式）
├── docs/
│   ├── DOCUMENTATION_MAP.md    # 文档地图（快速入口）
│   ├── DIRECTORY_STRUCTURE.md  # 目录结构说明
│   ├── WORKFLOW.md             # 主工作流（待创建）
│   ├── PRD.md / 技术方案.md / 执行计划.md
│   ├── ROADMAP.md              # 路线图
│   ├── SOP-wechat-channels-capture.md / SOP-wechat-official-article.md
│   ├── RESEARCH-video-quality-url.md / RESEARCH-wechat-channels-api.md
│   ├── DESIGN-knowledge-base-organization.md / 知识库规范.md
│   └── project-management/
│       ├── decisions/          # ADR决策记录（只增不改）
│       ├── memory/             # 工程记忆（跨会话稳定结论）
│       └── standards/          # 规范（待创建）
├── project-management/
│   └── active/                 # 活跃任务台账（动态）
│       ├── TASK_STATUS.md      # 当前进度、下一步
│       └── ISSUES.md           # 已知问题、阻塞项
├── tools/                      # 工具脚本（按功能分目录）
├── scripts/                    # 其他脚本（待整理）
├── data/                       # 本地运行数据（gitignore）
└── knowledge-base/             # 知识库成品
```

### 核心原则

1. **静态/动态分离**：docs/是静态规范，project-management/active/是动态状态
2. **文档地图优先**：新会话先读DOCUMENTATION_MAP.md定位
3. **ADR只增不改**：重要决策记录到decisions/，被取代时加演进注记
4. **工程记忆编译层**：memory/只放结论+指针，不复制原文
5. **问题驱动更新**：发现问题立即评估并更新文档或代码

## 后果

### 正面
- 文档结构清晰，AI和人都能快速定位
- 跨会话恢复有明确路径（AGENTS→DOCUMENTATION_MAP→memory→active）
- 决策可追溯，避免重复踩坑
- 工具和脚本按功能分目录，易于维护

### 负面
- 文档数量增加，需要维护
- 新增文档必须在DOCUMENTATION_MAP登记
