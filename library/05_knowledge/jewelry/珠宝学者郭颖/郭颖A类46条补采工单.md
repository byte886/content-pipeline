## 二、执行链路与纪律（防风控，硬性）

1. **取流走浏览器直读，不用 yt-dlp**：抖音匿名 ttwid 与 `--browser chrome` 均已于 2026-10-05 实测被拒。用浏览器（mac 为 `mac_computer_use_tool` plane=bu）打开视频页并**点播放**。**【2026-10-11 终版·currentSrc+__vid 铁证法，已取代旧 network 最高码率/差集法】** 抖音 web 的 `document.querySelector('video').currentSrc`（或 `.src`）直接是播放器**此刻真实播放**的完整 mp4 直链（非 blob: MSE；音视频合一，h264/hevc+aac），且 URL query 末尾带 **`__vid=<19位视频id>`** 身份参数——这是流与视频身份对应的铁证。导航 + `page_info` 标题校验后，**轮询 currentSrc（约每 2 秒一次，必要时 play/seek 促发，最多等约 40 秒）直到其 URL 含 `__vid=目标vid`**，以此为身份锚；再在 performance + network 已缓冲的 tos URL 中筛**同一 objectid（path 末段、去 query）且含同一 `__vid`** 的清晰度档、取 `br=` 最高者下载（同 objectid 必为同一内容，零身份风险；currentSrc 只反映播放器当前清晰度档）。**踩坑根因**：播放器初始化瞬间会先挂一个预加载/上一条残留的高码率流（br 反而更高），真实流稍晚才挂上；旧法"只等 9 秒 + 取全局最高 br / 播放前后差集最高 br"会误选该预加载流导致串流（批2 第 2、6 条曾下成别的视频，抽帧/转写发现后用铁证法纠正），**开新标签页隔离也不能避免**（污染发生在播放器/服务端层，不在 CDP target buffer 层）。`RENDER_DATA` 不含播放地址（走异步接口），不要从 SSR 找 playAddr。**仍须**：每条独立 cell、导航后先 `page_info` 校验 URL 含目标 vid 且标题正确；下载后 md5 两两比对（同批应全唯一）+ ffprobe（含 video+audio）+ 转写/抽帧做内容复核。完整可复用步骤见技能 `multiplatform-media-fetch/references/platforms/douyin-web-video-download.md`；收藏列表遍历见 `douyin-favorites-extract.md`。
